## 2. 数值范围保障与取整（核心改动）

### 2.1 现状

`_rebased_target` 只对 burghers 做两位有效数字量化：

```python
if pop_type == "burghers" and value > 0:
    quantum = max(Decimal("0.00001"), Decimal(1).scaleb(value.adjusted() - 1))
    value = value.quantize(quantum, rounding=ROUND_HALF_UP)
```

其余阶层仅经 `_clean_target` 的 0.01/0.001/0.0001/0.00001 分级步长，可能落在非两位有效数字上（如 `0.0525`）。

### 2.2 改法

把该量化从 burghers 推广到**全部七个阶层**：

```python
if value > 0:
    quantum = max(Decimal("0.00001"), Decimal(1).scaleb(value.adjusted() - 1))
    value = value.quantize(quantum, rounding=ROUND_HALF_UP)
```

`Decimal(1).scaleb(value.adjusted() - 1)` 即「10 的 (指数-1) 次幂」= 两位有效数字的量化单位。

### 2.3 范围保障的成立依据

`_format_float` 最多输出 5 位小数，且 `|x| < 0.000005` 时输出 `"0"`。量化单位恒 `>= 1e-5`，因此：

- **任何非零结果都是 1e-5 的整数倍**，必然能被五位小数精确表示，不会被 `_format_float` 静默截断
- **任何低于 1e-5 的正值量化为 0**，该商品从 `sol_unit_consumption_*` 中消失，而不是留下不可表示的残值

即：输出值域被钳在 `{0} ∪ [1e-5, ∞)` 且全部落在五位小数格点上。这正是后续 1340 中性校准需要的性质——校准量可以按同一格点做精确位移。

### 2.4 量化示例（实测上游值）

| good/pop | native×scale | clean | rebase | 量化后 |
|---|---|---|---|---|
| aromatics/nobles | 0.0525 | 0.05 | 0.05 | 0.05 |
| aromatics/burghers | 0.035 | 0.035 | 0.02294 | **0.023** |
| candles/laborers | 0.0000168 | 0.00002 | 0.00008 | 0.00008 |
| plaster/nobles | 0.13125 | 0.13 | 0.13 | 0.13 |
| ginger/peasants | 0.00001 | 0.00001 | 0.00004 | 0.00004 |

### 2.5 对既有 26 商品的影响

多数值本就是干净的两位有效数字，重算基线预期**基本不变**。真正会动的只有落在 0.0525 类「第三位非零」且非 burghers 的量。生成后需 diff 出实际变化清单并记录到文档——这是 1340 校准的起点，不能默默改变。

## 5. 风险

1. **`_rebased_target` 影响面是全部 30 商品**，不只新增 4 个。生成后必须 diff 出既有商品的数值变化清单。
2. **微小量归零**：`ginger`/`turmeric` 的 peasants 0.00004 保得住；但若后续校准把某量压到 1e-5 以下，该商品会从 unit consumption 消失而非保留残值。这是刻意的范围保障，需在 README 写明。
3. **`obsidian`/`jade` 归类易错**：它们是 `raw_material` 但有需求，若误入排除集，`_audit_workshop` 会报「excluded good unexpectedly has pop demand」。
4. **实机验收不可替代**：静态测试只保证生成一致性；JTG 加载顺序下的最终商品数、价格与求解器记账仍需实机确认。
