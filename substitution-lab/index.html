SOL · 商品替代组恢复方案

东西贵了，就换着买

商品替代组只做一件事：同一类东西里，某样变贵了，人们少买它，转去多买同类里便宜的。下面把恢复方案从价格一路算到游戏里的 modifier，每一步都能自己改数字看结果。

  4. 4钱守不守恒
  5. 5压成国家倍率
  6. 6写进游戏
  7. 7接入 SOL

1价格比决定"吸引力权重" v1.1 原样

每个市场里，每个商品有一个价格比 = 市场价 ÷ 默认价。价格比落进 7 档中的一档，每档对应一个权重：越贵权重越低（越不想买），越便宜权重越高。

边界是严格比较：价格比恰好 2.30 仍算"明显昂贵"（0.5），恰好 0.40 算"明显便宜"（1.5）。没有滞回，旧版每年一月刷新一次档位。

2同组商品互相比较 v1.1 原样

把一个组里所有商品的权重放在一起。某商品的需求倍率 D = 它的权重 ÷ 组内平均权重。

  • 全部价格正常 → 权重都是 1 → 每个 D 都是 1，什么都不变。
  • 只有一样变贵 → 它的 D 小于 1，其他所有同组商品的 D 都略大于 1。
  • 组内 D 的平均永远是 1：需求只是在组内挪来挪去。

竖线是 D = 1（不变）。取消"有供给"的商品被冻结在 1，不参与分配新方案；剩不到两个可买商品的组不替代。

v1.1 原公式里还有什么？为什么这里没有？

旧版直接把整条需求算出来：权重 ÷ 组权重和 × N × 阶层收入曲线 × 时代系数 × 10 ÷ 开发度。恢复方案只取其中"相对正常价格变了多少"的部分：用同一公式算一次当前价格、一次全部正常价格，两者相除就是上面的 D。阶层收入曲线、时代系数这些不再恢复，交给当前 SOL 的收入求解器，否则会和它重复计算。开发度抵消项当前分支已经关闭，也不照搬。

N 是组的商品数。在全部商品都有供给、且不考虑宗教文化偏好时，上面的公式化简后恰好就是"权重 ÷ 组内平均权重"。

3一个商品在两个组里：取平均 v1.1 原样

有 11 种商品同时属于两个组（比如布料既是"基本衣物"也是"标准衣物"）。它在每个组各算一个倍率，最后两个倍率取平均。旧脚本的 11 个汇总块全部写着 divide = 2，不是相加。

4倍率不等于钱：方案 A 还是方案 B 新方案 · 需二选一

D 只说"这个商品多买还是少买多少倍"。但组里商品原本花的钱可能差很多。一个商品原来占了 90% 的花费，它的倍率稍微降一点，组里总花费就明显下降。

方案 A：照旧版手感
直接用上面的 D。组内总花费会变。规格建议用这个。
方案 B：组内预算守恒
组里原来总共花多少，替代后还是多少，只按"原花费 × 权重"重新分。旧版没有这条规则。

商品乙

这里的"花费"按默认价计，是替代前的参照账本。方案 A 让总额变化并不是 bug：之后 SOL 的地点系数会按新篮子重新算总需求。两种方案不能叠用。

5一个国家只能写一个数 新方案

游戏只提供国家级接口 global_<商品>_pop_demand，没有市场级的。所以一个国家里，各地点、各阶层算出的不同 D，必须压成每个商品一个国家倍率 M：

M = Σ(原消费量 × D) ÷ Σ(原消费量)

也就是按"本来要买多少"加权平均。消费量按默认价换成金额来记账，对同一商品就等于按数量加权；故意不用市场价，因为市场价已经通过 D 起过作用，再当权重用一次就算了两遍。只统计这个国家自己拥有的地点。

例：一个国家有三个市场。改各市场的小麦价格比和小麦消费量（主食组其他商品都按正常价）。

"想要"和"实际"的差距就是精度损失：贵的市场减得不够，便宜的市场加得不够。全国总量是对的，分布不对。这个损失已经接受。

6写成 modifier 叠加方式待实测

每个商品定义一个国家静态 modifier，每月用 mode = replace 重写一次 size：

# main_menu/common/static_modifiers/SOL_substitute_global_modifiers.txt
sol_substitute_liquor = {
    game_data = { category = country }
    global_liquor_pop_demand = 1
}

# 每月
add_country_modifier = {
    name = sol_substitute_liquor
    months = 2
    mode = replace
    size = -0.2
}

直觉是 size = M − 1。问题在于同一商品可能已经有别的修正，例如原版时代 1 给烈酒 −75%。引擎是把它们相加还是相乘，目前没人测过。

7放进 SOL 现有流程

现在 SOL 已经有一条"市场支出 → 地点收入 → 国家求解器 → 地点 local_pop_demand"的链。替代要插在中间，并且整个国家用同一份快照：

  1. 每年 · 市场刷新按校准消费量算每个市场的支出。改：必须保留"每商品"明细，不能只存阶层总和——不同国家的 M 不同，总和没法复用。
  2. 国家 · 算替代遍历自己拥有的地点，算出全部商品的 M，算完再统一提交。新增
  3. 国家 · 写 modifier每个商品写一次 size，每月重写。新增
  4. 地点 · 算支出sol_compute_location_pop_demand 里每个商品支出乘上国家的实际倍率，再合计。改，前提是第 6 步的叠加方式已经测清楚
  5. 国家 · 阶层求解器不变。
  6. 地点 · local_pop_demand不变，继续只调总量；不再乘一次商品倍率。

缺缓存时一律 M = 1。关闭替代功能时，要对每个国家、每个商品显式 remove_country_modifier，不能只是"下次不算了"。国家 modifier 也会影响账本外的人口（如奴隶），验收时要看。

8特殊情况怎么处理

情况处理为什么
市场里没有这个商品冻结为 1，不参与本组分配不能把需求分给买不到的东西
组里只剩一个能买的整组不替代没有可替换的对象
商品没有 global_<商品>_pop_demand冻结为 1（如 PP 的加工食品）账本里改了而游戏里没改，账就对不上了
国家几乎不消费这个商品M = 1，移除 modifier避免除以接近 0 的数
功能关闭 / 国家失去全部领土显式移除所有替代 modifier防止旧值残留

9还没定的、必须测的

需要拍板
  • 方案 A 还是方案 B（规格建议 A）
  • 是否恢复宗教 / 文化 / 地点偏好（第一阶段建议不恢复）
  • PP 加工食品要不要补接口
  • Just Goods 的 26 种新商品归哪个组（默认不替代）
必须进游戏测
  • size = 0.25 是否真的让需求 +25%
  • 与时代等同商品修正相加还是相乘
  • 与 local_pop_demand、global_pop_demand 怎么组合
  • 负 size 和截断、人口需求多久滚动更新到位
