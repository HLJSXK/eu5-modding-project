READ THIS FIRST / 先把每个量说清楚

“基线金额”到底是什么？

这里的基线就是“这一轮替代还没有发生时，原本会花多少钱”。它不是商品价格，也不是国家 GDP，更不是已经替代后的金额。

01先确定谁在买

例如地点 A 里有 100 名农民。人口数量只决定“有多少个购买者”，本身还不是金币。

02再确定每人原本买多少

当前 SOL 的校准表可能给每名农民 0.02 单位小麦。100 人 × 0.02 = 2 单位小麦，这是数量基线。

03用中性参考价把数量换成金额

如果小麦默认价是 1 金币，就用这个默认价把 2 单位换成 2 金币：B=2×1=2。市场价 1.4 不进入 B；它只在前面的价格比 r=1.4/1=1.4 中影响替代权重。

04替代只改变“相对分配”

价格档位让小麦的相对权重变成 0.75，系统再和同组的稻米、玉米等一起重新分配。得到目标金额后，才计算 D = 目标 / 基线。

为什么国家聚合用 B，而不是直接平均价格？这里的 B 使用固定默认价，所以对同一个商品来说，按 B 加权与按数量 q 加权是同一件事；默认价只是把数量换成可读的金额单位。这样当前市场价不会同时影响“倍率 D”和“聚合权重 B”。
q数量基线人口 × 每人校准净消费量 × 是否有供应，单位是商品数量。
p_ref中性参考价格商品默认价；用于把 q 换成金额，和当前市场价无关。
B地点商品基线金额q × p_ref；替代之前、价格响应尚未改变时的中性参照金额。
B′地点商品目标金额应用价格替代后的理想支出；撇号 ′ 读作“替代之后”。
E国家基线金额把该国所有地点、人口类型的 B 加起来；同一商品等价于按 q 加权。
E′国家目标金额把所有地点、人口类型的 B′ 加起来；仍在地点总量系数重算之前。

04 / THE V1.1 MODEL

替代只是旧需求公式
其中的一层。

历史需求的量纲是交给引擎的商品倍率。收入曲线、储蓄压力、时代补偿、稀缺总量补偿和开发度抵消共同影响它，不能把整条旧链直接叠加进今天的 solver。

单组倍率 F(p,g,i) = Wᵢ / max(Σ Wⱼ, 0.001) × Ng × group_scale(p,g) × 10 / max(development, 1)
最终倍率 H(p,i) = Σ F(p,g,i) / 商品所属组数
01

POP 权重 W = T × V

T 是价格档位；V 是旧宗教、文化、气候和地点偏好。例如布料寒冬权重更高，葡萄酒有宗教禁忌、文化和祭仪偏好。这些规则运行在 POP scope。

国家主流宗教、地点 dominant culture 都不能冒充全部 POP 的偏好。国家 A 默认明确使用 V=1。

02

阶层组缩放

max(0, (1+savings_pressure) × demand_base × era × scarcity)

五阶层：贵族、教士、市民、平民、部落民。平民组缩放供劳工、农民、士兵共用。非部落需求基线是 GDP/人 × α/P + offset；部落民固定为 1。

03

引擎最后算实际需求

H 再与商品中各 pop_type 的基础需求以及引擎因子组合。权重份额归一化只约束倍率分配；价格、基础数量、group_scale 和跨组平均会改变实际支出。

当前已经关闭开发度需求倍率并抵消阈值。旧 10/development 必须留在历史对照里，不重复应用。

旧公式中每个字母究竟在表示什么？

p 是一个具体 POP；g 是一个消费组；i 是组里的某件商品。下面的 F 不是金币，而是“引擎商品基础需求上要乘的一个相对倍率”。

01W：这个 POP 对商品的相对偏好

W = 价格权重 T × 非价格偏好 V。假设一组有布料和皮革，当前权重是布料 0.5、皮革 1，那么两者合计 1.5；布料先得到 0.5÷1.5=1/3 的组内份额。

02N：历史组常数

例如两件商品的组 N=2，四件商品的组 N=4。它是 v1.1 设定的“这一组相对基础需求规模”，不是商品数量，也不是人口数量。

03F：这一个组给这件商品的倍率贡献

F = 组内份额 × N × group_scale × 开发度抵消。它回答“只看这一组，这件商品应该拿到多少倍率”。

04H：把商品所属的所有组合并

布料只在一个组时 H=F；葡萄酒同时在嗜好饮料和奢侈饮品两个组时，H=(F嗜好饮料+F奢侈饮品)÷2。v1.1 的真实脚本是取平均，不是直接相加。

05D：只保留价格造成的相对变化

恢复候选再用一遍全中性价格得到 H¹，用当前价格得到 Hᵀ；D=Hᵀ÷H¹。共同的收入、时代和稀缺规模不在这一步重复计算。

收入变化，旧组需求怎么走？

使用 v1.1 真实分段参数

横轴 GDP/人，纵轴 demand_base；3、8、25 为三个断点、四个区间。offset 来自真实脚本的五位小数输出，连接处可能有舍入残差。P 是该阶层篮子的基准价格总和，并非商品均价。P≈0 的一些组合在旧脚本中固定 base=1。图表仅复算旧 curve 与 group_scale，不是完整 POP/引擎模拟。

稀缺评分：另一条总量补偿

δᵢ = (1/Ptier − 1) × α四区间平均, 主组 / 主组成员数
scarcity_adj = 1 + Σ δᵢ

使用每商品唯一主组，四区间预算份额的平均，不是当期 α。Ptier 是价格阈值代表值，不是替代权重。缓存到市场中心，缺缓存时包装器回退 1。

旧刷新链与恢复边界

v1.1 一月先刷新价格列表，再算市场中心稀缺分数；每月刷新 savings pressure 和显示缓存。需求通过 POP script value 求值，并不是今天的月度地点修正链。

旧全刷新仅显式更新价格列表，不能声称初始化已经覆盖全部评分。新版必须自己建立完整快照。

05 / NATIONAL AGGREGATION

同一国家，只能得到
一个商品倍率。

先计算所属地点和七类人口的本地响应，再用中性参考金额聚合。人口已包含在 B 中，不重复加权；市场拥有者也不等于该市场全部消费人口的国家。

第 1 步：数量 q = 这类人口的人数 × 每人原本会消费的校准数量 × 市场中确实有货（有货=1，无货=0）。
第 2 步：中性参考价格 pref = 商品默认价；它只把数量换成金额单位，不读取当前市场价。
第 3 步：地点基线金额 B = q × pref。这是“替代发生前、以中性价格计量的参照金额”。
第 4 步：国家基线金额 E = 把该国所有地点和人口类型的 B 相加；国家目标金额 E′ = 把替代后对应的 B′ 相加。对同一个商品，pref 在所有地点相同，所以 E′÷E 等价于按数量 q 加权。
第 5 步：国家倍率 M(C,i) = E′ ÷ E；它回答“该国这个商品的目标数量，是中性基线数量的几倍”。E≤epsilon 时不计算小数比值，直接回到 M=1。
基线金额的边界

B 是一个“替代之前的中性参照账本”。它不是玩家手里的钱，不是商品当前售价本身，也不是把所有消费组加起来的总 GDP。它只描述一项明确的数量基线：某地点、某人口类型、某商品原本会消费多少，再用固定默认价换成金额。当前市场价只进入 r=市场价/默认价，通过 v1.1 的价格档位影响 D。

当前 SOL 的确另有一个支出缓存，会用 min(市场价,默认价) 抑制高价对 raw spending 的影响；那是地点总量 / 收入闭合的支出代理，不是替代发生前的 B，不能在 D 已经使用市场价后再次拿来做国家聚合权重。

TWO-MARKET COMPRESSION

两市场的精度损失，直接算给你看

这是同一商品的聚合专用实验；D 可独立输入，表示“这个市场中，该商品目标数量 ÷ 该商品中性基线数量”。q 已经包含人口，所以不要再乘一次人口。每一行先得到中性参考金额 B=q×pref，再得到本地理想金额 B×D；国家不会保存两个 D，而是把各行 B 加成 E，把各行 B×D 加成 E′，只输出一个 M=E′÷E。

读表例子：市场 A 若 B=1、D=0.5，理想金额就是 0.5；市场 B 若 B=2、D=1.5，理想金额就是 3。国家 E=3、E′=3.5，所以 M=3.5÷3=1.16667。国家 modifier 只能表达这个 1.16667，不能同时让 A 精确得到 0.5、B 精确得到 1.5。

为什么不用人口平均？

人口结构决定商品基线需求；贵族买马、平民几乎不买马，商品数量与总人口不成正比。数量口径和金额口径也不同。候选固定金额口径，对齐现有支出模型。

保住总金额，不保本地精度

当 E>epsilon 时，统一 M 在地点系数重算前保住该商品目标总金额，但不保各市场、各阶层的数量。solver 重算地点 L 后，总金额也可能再次变化。

小额 / 零需求要中性回退

E≤epsilon：M=1、size=0，移除旧修正。不能用 max(E,0.001) 抬高正分母；否则 E=E′=0.0005 会错误地得到 M=0.5。冻结不能凭空创造基线为零的需求。

ENGINE SEMANTICS / 假设模型，非引擎结论

为什么 size 不总是 M − 1？

必须游戏验证

先把两个数分开：M 是“最终希望达到的总倍率”；size 是“要写进 modifier 的参数”。如果游戏里已经有时代或机构给出的同商品修正，size 必须考虑它已经占掉的那一部分。只有确认引擎怎样合并这些来源后，才能把 size 简单写成 M−1。

更大的前置条件：商品 × 地点是否真是乘法？

若国家商品修正与 local_pop_demand 相加，一个国家商品值加一个地点总量值就不能表达 M(i)×L(l)。这种情况需要调整整个接入模型，而不只是换 size 公式。外部 e 的读取必须排除自身旧值，避免刷新自我累积；无法对齐的商品保持中性，账本不假定它已生效。

07 / SOL INTEGRATION

改变消费篮子后，
收入求解器必须同步重算。

替代决定买什么；现有 SOL 地点系数和国家四类 solver 处理总量与收入目标。二者共用同一快照，旧恩格尔缩放、时代补偿和稀缺总量补偿不重复接入。

先分清两个“需求”：商品替代回答“钱在同组商品之间怎么移动”；地点 raw spending 回答“这个地点总体能承担多少消费”；国家 solver 再把各地点的总体系数调整到国家收入目标。商品倍率不能代替地点总体系数，地点总体系数也不能重新分配商品。

所有商品一起涨价，为什么可能不发生替代？

若同组所有商品进入同一档且偏好不变，归一化时共同 T 消去，相对中性响应仍为 1。这不代表价格没有影响支出；价格代理和总量 solver 是另一层。

为什么不能把旧所有 scale 也搬回来？

今天已经有校准后的净单位消费量和收入闭合。旧 Engel、储蓄、时代和稀缺总量补偿若再次叠加，会重复调整总量。方案 A 仅提取价格相对中性响应，不声称还原旧阶层曲线。

两国同处一个市场，国家 M 一定一样吗？

不一定。每国只聚合自己拥有地点的需求金额，商品基线和人口结构可能不同；还可能各自包含其他市场。若单市场、V=1、所有记录同组有效集与 D 完全相同，才会得到相同响应。

既然接受精度损失，为何还要展示误差？

接受国家压缩意味着接受各市场不能独立生效，不意味着数量、金额、阶层同时精确。明确这些边界有助于判断后续 solver、兼容和 tooltip 是否与真实生效规则一致。

10 / SYMBOLS IN PLAIN LANGUAGE

把每个符号翻译成人话，
再看它怎样走到国家倍率

下面的顺序就是一次计算真正经过的顺序。先算“原本会花多少钱”，再算价格响应，最后把一个国家所有地点的结果压缩成一个国家级接口；每个符号都说明它的单位、来源和下一步用途。

先记住三种单位：数量、单价、金额。

q 是商品数量（件、单位或游戏内部的消费单位）；p 是每一单位商品的价格；B、E 和 E′ 是货币金额。金额一定是“数量 × 单价”，倍率没有单位。把价格、数量和金额混叫成“需求”会让后面的守恒和国家压缩都失去含义。

i / l / s / m / c
它们是谁：i 是商品，l 是地点，s 是人口类型，m 是市场，c 是国家。为什么需要：同一种商品在不同地点、不同人口类型、不同市场可能有不同价格和消费量；国家级 modifier 只保留 c 这一层。
q(l,s,i)
它是什么：替代发生前，地点 l 的人口类型 s 原本要消费的商品数量。来自哪里：人口数量乘以当前校准的净单位消费量（历史曲线章节里的旧模型则使用对应的历史需求输入）。下一步：与固定的默认价相乘，得到中性参照金额；它不是人口数，也不是钱。
p_market / p_default
p_market：这个市场此刻的实际单价。p_default：商品的默认或中性单价，用来规定“价格没有偏离”时的基准。两者都是“货币 / 一单位商品”，不是总支出。
p_ref = p_default
它是什么：替代聚合使用的中性参考单价。它来自商品默认价，和地点当前市场价无关。对同一个商品，所有地点的 p_ref 相同，所以用 B=q×p_ref 做金额加权，数学上等价于直接用数量 q 加权。当前 SOL 另有一个 p_eff=min(p_market,p_default) 的 raw spending 代理；那个公式不属于 v1.1 替代组，也不应被塞进这里的 B。
B(l,s,i) = q × p_ref
基线金额到底是什么：先假设替代组还没有改变购买比例，地点 l 的人口类型 s 仍要买 q 数量，再按商品默认价 p_ref 计价，得到一笔不受当前市场价格影响的中性参照金额。例：100 人每人消费 0.2 单位，q=20；默认价为 3，则 B=20×3=60。它不是：商品当前市场售价、人口、GDP、玩家现金，也不是替代后金额。为什么先算它：后面所有倍率都作用在这笔可追溯的中性基线上，当前市场价只通过 D 改变相对分配，不会同时改变权重基数。
当期 / 中性
当期：使用当前市场价格比，记为 r = p_market / p_default；它回答“现在价格处在这个位置时，组内购买倾向怎样变化”。中性：把价格比强制设为 r=1，其他输入（人口、商品、供给、接口）保持相同；它回答“没有价格偏离时，系统会给出什么结果”。中性不是另一个市场，也不是把所有商品删掉，而是同一套计算的对照组。
T / V / W=T×V
T：价格档位权重，来自六档价格响应曲线；它表达价格比落在哪一档。V：非价格偏好（宗教、文化、气候、地点等可能因素）。本恢复方案默认 V=1，意思是暂时不额外偏爱或排斥任何成员。W：两者相乘后的组内权重；它仍是“相对权重”，不是数量、金额或预算。
N / 有效成员数
N：v1.1 历史脚本里的组倍率常数，属于旧模型参数。有效成员数：新接口计算时实际通过供给、目录和接口检查的成员数量。两者可能不同；不能把旧的 N 当成今天一定存在的商品数。
F / H
F：先在一个替代组内部，把每个成员的 W 转成份额并汇总后的单组倍率。H：同一个商品如果属于多个组，就分别算出它在每个组的结果，再按规则平均这些组结果；H 是跨组平均后的商品倍率。跨组平均不是把商品重复购买两次，而是把多个组给出的意见合成一个倍率。
D = H_current / H_neutral
它是什么：最终的相对价格响应。先用当期价格算一次 H_current，再用中性价格算一次 H_neutral，两者相除得到 D。例：当期跨组平均为 0.8，中性为 1.0，则 D=0.8/1.0=0.8，表示相对中性少 20%。为什么要除：这样取消组内共同的绝对尺度，只保留价格偏离造成的相对变化。
B′ = B × D
它是什么：替代后、地点系数重算前的目标金额。继续上面的例子，若 B=60、D=0.8，则 B′=48。这一步保持旧价格响应的形状，但不承诺所有商品金额之和不变，也不承诺数量守恒；收入 solver 和地点总量调整属于后续层。
group_scale = 1 / V=1
这是恢复方案的有意边界。group_scale=1 表示不再把旧收入、储蓄、时代或稀缺总量曲线重复乘进新倍率；V=1 表示不加入尚未验证的非价格偏好。它们不是“永远没有这些机制”，而是先把新接口能证明的价格响应隔离出来，避免同一影响被算两遍。
E(c,i) = Σ B(l,s,i)
它是什么：国家 c 在所有所属地点和人口类型上，对商品 i 的基线金额总和。求和发生在地点系数重算之前；每个 B 仍可追溯到具体地点和人口类型。下一步：把同样的 B′ 相加得到国家理想目标金额 E′。
E′(c,i) = Σ B′(l,s,i)
这是国家商品 i 在替代响应后的理想目标金额，仍然保留了每个市场各自的结果后才聚合。它不是已经写进游戏 modifier 的值；modifier 还需要把它压缩成一个国家级倍率。
M(c,i) = E′ / E
它是什么：国家级 global modifier 的目标相对倍率。例：若一个国家的 E=3、E′=3.5，则 M=1.16667，表示国家总目标金额比基线高约 16.667%。它不是：市场价格，也不是每个市场都精确相同的倍率。金额为零时使用页面设定的 epsilon 小额回退，避免用零作分母制造无意义的无限大。
为什么会损失国家级精度
市场 A 若 B=1,D=0.5，市场 B 若 B=2,D=1.5，则国家 E=3、E′=3.5、M=1.16667。把同一个 M 写回两地后，A 会得到约 1.16667 而不是 0.5，B 也会得到约 1.16667 而不是 1.5。国家接口保留了总额方向，却不能同时保留两个市场的独立响应；这正是“国家级实现可接受但不如市场级精确”的具体含义。
size
它是什么：写入 add_country_modifier 的参数，不自动等于 M。若引擎把同类百分比修正相加，目标相对倍率常见候选是 size=M-1；若引擎把独立因子相乘，候选写法和已有 offset 不同。必须用单独实验确认加法、乘法、覆盖、截断和滚动更新，不能仅凭 percent=yes 这一行定义推断。
守恒 / 不守恒
金额守恒：替代前后所有成员金额加总相等；数量守恒：所有成员数量加总相等。方案 A 只保证相对价格响应形状，不保证这两种守恒；方案 B 才是额外设计的预算守恒版本。即使金额不守恒，也不代表计算错误，而是意味着后续 solver 必须承担总量和收入闭合。
raw spending / L
raw spending：地点在现有收入闭合规则下总体能承担多少消费的原始系数；它回答“这个地点总共花多少”。L：国家 solver、收入和地点约束处理后的最终地点需求系数。商品 D 回答“同组商品之间的钱怎样移动”，raw / L 回答“地点总量是多少”；两者不能互相替代，也不能把国家商品倍率重复乘进地点总量。
global_<good>_pop_demand 与 owner(c)
前者是“对国家内所有人口类型的该商品需求一起施加修正”的候选接口；后者表示地点所属国家，用来查找该国家的 M(c,i)。接口存在不等于组合语义已被游戏验证，仍需检查商品是否真的读取它、同类 modifier 如何合并，以及人口需求滚动何时刷新。
读公式时的固定顺序

先得到数量 q → 取默认价作为中性参考价 p_ref → 算基线金额 B → 当期与中性各算一次组内倍率 → 跨组平均成 H → 相除得到 D → 得到 B′ → 国家内分别加总成 E 与 E′ → 相除得到 M → 再根据经过实测的引擎语义换算 size。任何一步缺输入，都应冻结为 M=1 并标记待初始化，而不是猜一个商品倍率。
