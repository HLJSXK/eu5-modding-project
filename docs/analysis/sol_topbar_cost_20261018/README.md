# SOL topbar / 左侧生活水平行：额外月度脚本操作估计

依据：2026-10-18 最新自动存档 `autosave_b2df3bea-4910-48cc-b130-7489fa025098.eu5`，游戏日期 **1338.4.1**，EU5 1.4.1。当前生成后的 stable 收入和排名脚本离线回放；源码 SHA256 保存在 [counts.json](counts.json)。统计的是整个 HUD 后端带来的新增成本，包括收入汇总、同月历史和全球排名。

存档有 2,386 条国家记录，其中 1,600 国拥地且有人口。唯一玩家为匈牙利，189 个地点；1,599 个 AI 共 13,399 个地点。所有已拥有地点都有收入缓存，1,600 国有当前 PCI，7 国已有同比。存档全局 `sol_ai_reduced_freq_enabled` 为 boolean、identity=1。

## 计数口径

**1 次操作 = 1 个实际执行的非分支 effect 节点，或 1 个实际访问的条件节点。** 包含脚本 helper 调用、变量写入、作用域切换；不把 if/else 分派、右侧算术、getter 内部实现另计。沿用项目旧性能审计的脚本节点口径。

收入逻辑嵌在已经存在的经济求解遍历中，不重新计入原有地点遍历、求解器、替代商品算法和 modifier 更新。GUI 每帧绑定、悬停绘制、原生排序比较与引擎内部耗时不在这里。因此数字不能转换成 CPU 指令数或毫秒。

## 存档规模下的结果

| 新增工作 | effect | 条件 | 合计 |
|---|---:|---:|---:|
| 玩家一次月度收入更新 | 2,921 | 46 | **2,967** |
| 所有 AI 各更新一次，作为全年工作规模 | 350,796 | 72,492 | **423,288** |
| 上项除以 12，AI 每月平均 | 29,233 | 6,041 | **35,274** |
| 一次全球排名，所有存档国家记录均参与筛选的保守计数 | 45,533 | 48,665 | **94,198** |
| 一次全球排名，仅 1,600 个活跃国家参与筛选的敏感性计数 | 40,031 | 47,093 | **87,124** |

两个排名估计都实际排入 1,600 国。差额来自是否为其余 786 个国家记录执行清理与资格筛选；离线解释器没有复现原生 `every_country` 的存活过滤。原生排序内部成本没有被这个上下情景量化。

按 AI 周年更新分摊，而非假设它们都在一月执行：

| 场景 | 额外操作 |
|---|---:|
| 普通月平均：玩家 + AI 年度工作 / 12 + 排名月份判断 | **38,242** |
| 一月：再加一次全球排名，仍以平均 AI 周年工作计算 | **125,366–132,440** |
| 排名也摊入全年后的月均 | **45,502–46,092** |
| 若把 AI 改为每月完整计算，含年度排名摊销 | 约 **434,106 / 月** |

**这不是某个具体月份的逐国调度预测。** 没有从存档中取得原生年度 pulse 的完整日期表；AI 的真实月度工作随周年分布变化。“所有 AI 各更新一次”是在该存档日期回放保存的历史状态，用来估计数量级。未来人口、收入、基线和领土变化都可能改变分支。

## 首次计算与成熟历史

- 把同比历史清空时，普通月平均约 **30,195**，排名摊入全年约 **37,455–38,045 / 月**。
- 保存的拓扑配上成熟的同月历史时，普通月平均约 **38,367**，含排名摊销约 **45,627–46,216 / 月**。
- 初始化需要一次全世界收入汇总和排名：首次历史约 **424,468**；按当前保存的历史做一次全局刷新约 **520,453**。这是已有全局刷新入口增加的单次成本，不是每月固定执行。

## 成本来自哪里

每个地点额外执行 **12 次累加变量写入**：总收入、总人口，加五个阶层各自的收入、人口。再计调用、保存地点 scope 和切到 owner，合计 **15 次 effect / 地点 / 求解**。不含 getter 内部运算。

匈牙利为 `189 × 15 = 2,835` 次地点相关操作，再加 132 次国家清零、PCI 发布、历史、同比等操作，得到 **2,967**。AI 全年地点部分为 `13,399 × 15 = 200,985`，其余 **222,303** 来自 1,599 国的国家级汇总与历史处理。

全球排名只读国家缓存：一次清理/人口加权汇总，再一次排序后的国家遍历；没有地点扫描或国家两两比较脚本。
