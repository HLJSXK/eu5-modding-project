# Standard of Living - 详细功能说明

## 当前状态

**版本：** v1.3 beta  
**范围：** 本版本仅包含基础 SOL 人口需求缩放，以及下文列出的保留平衡系统。  
**目标环境：** Europa Universalis V 1.3 beta / 元数据目标为 1.*  
**依赖：** Community Mod Framework 2.* 用于游戏内配置。

本版本存在的原因是：EU5 引擎改动破坏了旧版 SOL 1.2 需求架构。当前版本故意收窄范围，保留校准后的人口需求基线，并用更稳定的本地需求系数替代旧实验链条，通过 `local_pop_demand` 施加效果。

由于引擎无法干净支持旧实现，因此没有 v1.2 Workshop 版本。若需要旧版 v1.1，请使用：

[v1.1 版本 - Standard of Living](https://steamcommunity.com/sharedfiles/filedetails/?id=3706951645)

## 相比旧版已移除的内容

以下系统不再属于 EU5 1.3 beta 版本的运行时内容：

- 替代商品组系统。
- 市场稀缺档位。
- 逐商品需求再分配。
- 按阶层分段恩格尔曲线链条。
- 市场中心稀缺修正。
- 基于 `sol_era_coeff` 的旧版再分配逻辑。

仓库中可能仍保留旧数据和旧脚本作为参考，但它们不属于当前活跃玩法。

## 设计目标

原版人口需求过于静态，而 SOL 希望构建一种更能反映经济能力的需求模型：

- 更富裕的地点应当能够消费更多。
- 更贫穷或地产建筑负担更重的地点应当消费更少。
- 阶层存款应当影响全国消费压力。
- 发展度仍应通过引擎自带需求除数发挥作用。
- 市场价格应当影响基础支出，但高价商品不应无限抬高基准。

因此，当前版本采用了更轻量、更容易在 EU5 1.3 引擎下维护的模型，同时让人口需求比原版更动态。

## SOL 核心需求系统

### 1. 校准后的基础需求

SOL 通过 `demand_add` 注入重新校准 55 种商品的人口基础需求。

来源流程：

```text
data/target_demand.csv
-> scripts/gen_pop_goods.py
-> src/stable/in_game/common/goods/z_SOL_pop_goods.txt
```

这条基础需求非常重要。月度 SOL 乘数会缩放这些修正后的 `demand_add` 数值。如果移除这条基线，就会在 SOL 乘数施加之前改变人口需求的绝对值。

### 2. 市场单位支出缓存

SOL 每年扫描一次全世界市场，并保存以市场作用域为键的支出映射。对每个 pop 类型和商品，单位基础支出使用以下方式计算：

```text
单位消费数量 * min(市场价格, 默认价格)
```

也就是说，便宜商品可以降低基础支出，但昂贵商品不会把基准无限推高到原版默认价格之上。

当前市场缓存使用以市场作用域为键的 `global_variable_map`，不再依赖市场中心地点变量。

### 3. 地产建筑维护费

SOL 每年扫描每个有主陆地地点，并按地产类型统计地产建筑：

- 贵族
- 教士
- 市民
- 平民
- 部落民

每个已缓存的地产建筑都会从对应阶层的本地收入中扣除 1 金币。这使地方地产建设会影响对应阶层的消费能力。

### 4. 月度本地需求系数

每个月，各国会刷新自己拥有的陆地地点。SOL 使用以下关系计算本地最终需求系数：

```text
本地流动资金 / 发展度修正后的基础支出
```

其中：

- 本地流动资金来自扣除地产建筑维护费后的本地阶层总收入。
- 全国存款压力会调整收入中有多少被视为可用于消费。
- 基础支出来自市场单位支出缓存乘以本地人口数量。
- 发展度修正后的基础支出会把基础支出乘以 `(1 + development / 20)`。

最终结果通过以下地点修正施加 1 个月：

```text
sol_local_pop_demand_modifier
local_pop_demand = 1
size = 最终需求系数 - 1
```

### 5. 生活水平 UI

SOL 增加了用于查看系统状态的界面：

- 全国生活水平局势。
- 基于本地需求系数缓存的地图着色。
- 地点级 SOL 面板和提示信息。
- 手动刷新缓存操作。
- 收入、存款、维护费、基础支出、流动资金、最终系数等显示行。

## 经济平衡系统

以下内容与 SOL 需求模型一起保留。

### 时代经济递增

经济压力会随时代推进而增长。到第 6 时代时，累计效果达到：

| 效果 | 第 6 时代累计值 |
|---|---:|
| 全局建筑效率 | -100% |
| RGO 扩张成本 | +100% |
| 城市升级成本 | +50% |
| 城镇升级成本 | +50% |
| 人口食物消耗 | +50% |
| 全局月度繁荣 | +0.001 |

早期世界具有轻微繁荣稀缺；后期世界更加繁荣，但扩张成本也显著升高。

### 反滚雪球建设

SOL 通过改变基础建设激励来放慢无脑扩张：

- 基础 RGO 规模降为 1。
- 总人口带来的 RGO 规模增长降低。
- 低控制力地点获得建筑效率惩罚。
- 道路和铁路价格提高：

| 行动 | SOL 成本变化 |
|---|---:|
| 碎石路 | x2 |
| 铺装路 | x2 |
| 现代道路 | x3 |
| 铁路 | x5 |

### 税收、难度、外交与发展度

- 基础税收效率默认为 **-15%**，可通过 CMF 调整。
- AI 困难 / 极难难度税收加成减半。
- 玩家简单 / 极简单难度税收加成减半。
- 外交支出会随已使用外交容量变化。
- 文化传统可以降低稳定度投资成本。
- GDP 转发展度会按本地 GDP 每年提供发展度增长。
- AI 国家可以获得可配置的荒废度恢复加成，帮助负繁荣地区恢复。

## 战争与扩张系统

### 更严苛的厌战

厌战更加危险，可能进一步削弱或损害：

- 征召规模。
- 控制力。
- 稳定度。
- 合法性。
- 防御能力。

占领压力也更高：

| 条件 | SOL 效果 |
|---|---:|
| 全境占领 | 在原版基础上额外 +1.6 月度厌战 |
| 首都被占领 | 在原版基础上额外 +0.2 月度厌战 |

降低厌战内阁行动可以通过 CMF 设置为仅和平时期可用。

### 地方战争创伤

战争相关地点修正更加严苛。以下状态会更明显地影响繁荣、控制力、建设、迁移吸引力、发展、原材料和食物：

- 封锁。
- 围城。
- 占领。
- 敌军存在。
- 劫掠。
- 游牧劫掠。
- 焚掠。

### 殖民限制

AI 通常需要超过 **500 税基** 才会建立殖民特许。

例外：

- 历史殖民国家不受该税基限制。
- 殖民地国家只能在首都所在大区殖民。
- 玩家不受该规则限制。

### 外交行动抑制

请求其他国家加入战争需要更多 favors，用于减少无脑召唤参战。

## 食物、气候与价格平衡

### 食物与气候

- 普通冬季和征召民兵会带来更强的本地食物压力。
- 小冰期极端食物和产出惩罚被缓和，以减少纯粹的灾难螺旋。

### 价格再平衡

多项金币转移和行动价格被重新平衡。例如：

- 将军需要金币。
- 海军将领需要金币。
- 顾问和艺术家需要金币。
- 多项宗教与外交行动调整了金币缩放或上限。
- 道路和铁路更加昂贵。

## CMF 设置

Community Mod Framework 2.* 可以在游戏内控制 SOL 的主要模块。

| 设置组 | 控制内容 |
|---|---|
| SOL 人口需求 | 总开关、地图着色 |
| 经济平衡 | 总开关、基础税收效率、时代经济递增、稳定投资折扣、外交支出调整、难度税收削弱、GDP 转发展度、AI 繁荣恢复 |
| 战争加速 | 总开关、更高厌战、更严苛厌战效果、战时降低厌战限制 |

当 CMF 变量不可用时，许多系统有默认开启的回退行为；但 Workshop 包声明 CMF 为依赖，因此仍建议启用。

## 兼容性

旧存档可以加载，但推荐开新档。

旧存档首次加载时可能出现迁移提示。加载后，经济可能需要一些时间刷新市场缓存并重新稳定价格。

不保证与其他模组兼容，尤其是编辑以下内容的模组：

- 人口需求。
- 商品定义。
- 本地或国家经济修正。
- 厌战。
- 殖民特许。
- 道路或行动价格。
- 生活水平 / 局势 GUI。

我目前无法稳定进行 EU5 1.3 长局测试，因为本人这边长局会持续崩溃。如果你发现具体冲突或平衡问题，请反馈给我，我会尝试修复。

## 推荐加载和游玩说明

- 使用最新 Workshop 版本 SOL。
- 启用 Community Mod Framework 2.*。
- 测试平衡时推荐开新档。
- 如果加载旧档，请让游戏运行一段时间，让年度和月度缓存完成刷新。
- 多人游戏中，所有玩家应使用相同模组版本、相同依赖和相同 CMF 设置。

## 反馈模板

反馈问题时，请尽量提供：

- 游戏版本。
- SOL 版本。
- 新档还是旧档。
- 国家和年份。
- 启用的其他模组。
- 是否修改过 CMF 设置。
- 问题发生前后出现了什么变化。
- 截图或日志，如果有的话。

比较有用的反馈示例：

- 某种商品需求长期明显过高或过低。
- 某个国家以可复现方式经济崩溃。
- SOL 地图着色或面板数值看起来不正确。
- 厌战或殖民限制表现异常。
- 某个兼容性冲突可以用较小模组列表复现。
