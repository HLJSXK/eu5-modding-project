### 3.1 改动 C1：酒背景改为静态地区参数

**规则**

1. 删除酒的模拟器对象（`structural.py:462-478` 的 `context_goods["wine"]`，以及 614、643、905–906、1096–1108 等处对它的全部引用和 U 计费）。删除 `structural_config.json` 中 `initial_customs.wine`。
2. 新增固定配置 `wine_background`，内容逐字如下：

```json
"wine_background": {
  "regions": ["italy_region", "france_region", "iberia_region"],
  "religion_group": "christian",
  "value": 30,
  "grade": "C",
  "source": "26 §3.1: Mediterranean wine-dominant drinking belt; static design context, not fitted"
}
```

3. 地点 v 的酒背景 = `value`，当且仅当：v 的地图属性 `region` 在 `regions` 中，**并且**当前世界状态下 v 的宗教组等于 `religion_group`。否则为 0。
   - `region` 读静态地图属性。
   - 宗教组读当前 `state.religion_group[v]`。O 世界里宗教会变，就按当月状态取。
   - 不读国家，不读所有者。
4. `preemption_load(good, v)` 的公式不变，只替换酒的来源：`rival = max(对手商品的全量国家聚合, 酒背景(v))`，`b = preemption × max(0, rival − 20)`。仍然只对咖啡和茶生效，烟草不受影响。
5. `preemption_load` 不新增 U 计费项。原酒模拟器的计费随对象一并删除。
6. 对照开关 `wine`（25 中的「移除酒背景」）改为：所有地点酒背景为 0。

- `test_no_wine_simulator`：运行中不存在酒模拟器，总 U 中没有酒的项目。
- `test_wine_ablation_zero`：关闭 `wine` 后全部为 0。

### 3.2 改动 C2：开局习俗区定格

**规则**

1. **习俗区的定义。** 对 `initial_customs` 中的每个商品 g（本轮是 tea 和 tobacco），每一条 `where` 只按**静态地图属性**匹配（`region`、`area`、`raw_material`、`continent` 等，以 `graph.attrs` 为准）。所有匹配地点的并集就是 Z_g，习俗值取该条的 `value`。同一地点匹配多条时取最大值。
   - 在 R 和两个 O 世界中 Z_g 都相同，不读所有者、市场、人口或存档值。
   - 咖啡没有习俗区。
2. **定格。** 对 v ∈ Z_g：
   - x_v 在整个运行中恒等于 x⁰_v。
   - v 永不入队、永不被服务。`_push` 对 v 返回拒绝，计费同 `push_rejected`。
   - v 不接收任何输入。邻接、同市场、商人、领地、事件、种子都不行。`inject` 对 v 返回 False，并计入新计数 `zone_rejected_inputs`（按商品分列）。
   - v 的有效值 `eff(v)` 恒为 x⁰_v，**不受**其所有者是否退潮影响，不乘 S 或 habit。
   - 退潮定格时的重归一化循环（`core.py:474,485` 及 `structural.py:404-408` 的物化循环）跳过 v。
3. **不向区外邻接输出。** 对任何非习俗区地点 w，计算邻接输入时跳过所有来自 Z_g 的入边。
   - 实现方式：载入时为每个商品预先构造「去掉 Z_g 来源」的入边表，运行时不做逐边判断。
   - `_note` 中用于判定到达类型的邻接求和（`structural.py:157-159`）也用这张表。
4. **同市场带动。** 非习俗区地点 w 收到的同市场输入，`internal_rate × 市场开放聚合`（`structural.py:192`），改用**开放聚合**。
5. **作为来源时照常读值。** 以下几处读的是**全量**值（习俗区按 x⁰_v 计）：
   - 商人常驻的来源市场条件 x̄_M ≥ θ，以及反向常驻的 `source_countries`（`structural.py:720-729`）；
   - 领地回流的「热区人口」：x ≥ 20 的地点（`owned_hot_population`，`structural.py:307`）。习俗区地点照常计入；
   - 领地回流的来源地点条件 `eff(source) ≥ 20`；
   - 先占中「对手商品的国家聚合」；
   - 所有判分和诊断：里程碑、K 条、健全性、`country_value`。
6. **国家时钟不由习俗区触发。**
   - 习俗区地点不构成「首次接触」。
   - 「全国流行」用开放聚合判断（§3.3）。
   - 一个只拥有习俗区地点的国家，D 永远为 −1。
7. **删除旧的开局处理**：`structural.py:510-530` 里把习俗国家标记为 `finished`、清空 `join` 的那段代码。保留其中「开局只学习已有接触对和领地对、不开波」的逻辑（`seen_pairs` / `seen_ownership` 的初始化、`opening=True` 的调用）。
8. 新开波时（`structural.py:398-414`）对 Z_g 地点不做任何事。

**边界情况（已有定论，不要再问）**

- 习俗区地点被征服或换了所有者：值不变，依然定格。新所有者如果首都不在流行区，可以通过领地回流把它当来源。这是本轮唯一能让茶出东亚的结构路径之一。
- 美洲烟草习俗区是零散的原料地点。卡斯蒂利亚取得 `magorix` 后，`magorix` 作为领地回流来源（30 ≥ 20），但**不**启动卡斯蒂利亚的时钟。
- 习俗区地点所在的国家进入退潮时，同一国家里的非习俗区地点照常退潮，习俗区地点不变。
- 首都在习俗区的国家（如中国、日本）：首都有效值不低于 20 时，领地回流条件「首都 < 20」不成立，不向首都注入；商人注入首都会被拒绝，并计入 `zone_rejected_inputs`。
- 朝鲜习俗值恰好是 20：「≥ 20」成立，「< 20」不成立，按字面执行。
- 第 4 条只排除习俗区对同市场带动的贡献；**市场全量聚合**仍用于第 5 条的来源判断。两个聚合都要维护。

**测试**

- `test_zone_static_membership`：Z_tea、Z_tobacco 由配置唯一确定；改变所有者或市场后集合不变。
- `test_zone_values_frozen`：合成图，开波后跑 600 月，习俗区地点的值逐月不变。
- `test_zone_no_adjacency_export`：三点链「习俗区 45 — 空地 — 空地」，空地永远收不到邻接输入。
- `test_zone_no_market_export`：同一市场里的非习俗区地点，同市场输入只按开放聚合计算。
- `test_zone_source_for_contact_and_ownership`：习俗区计入市场全量聚合和领地热区人口；外国常驻商人可以把它当来源。
- `test_zone_rejects_inputs`：对习俗区地点的商人、领地、事件注入均被拒绝，计数正确。
- `test_zone_exempt_from_decay`：所有者退潮并定格后，习俗区地点的 `eff` 仍为 x⁰。
- `test_zone_does_not_start_clock`：国家只拥有习俗区地点时 D = −1；获得一个非习俗区地点并达到 x ≥ 1 后才设置 D。

### 3.3 改动 C3：国家时钟改为截止月 D

**规则**（只在 structural 层生效）

1. 每个国家×商品只存一个整数 D，替代 `join`。初值为 −1。
2. **首次接触。** 当国家 c 的某个非习俗区地点首次达到 x ≥ 1，且 D[c] = −1 时：
   - 设 `D[c] = t₀ + L + T`，其中 L = 1200，T = 240（§5.2）。
   - t₀ 的取法与现有代码相同：被服务时为当月 t；经 `inject` 达到时为当月 t；种子成员按 `core.py:440-443` 的规则取已配置的种子月份与当月中较早者。
3. **全国流行。** 每月在时钟步骤中，对每个 D ≠ −1、未在退潮、未定格的国家：如果它的**开放**国家聚合 ≥ θ（20），则 `D[c] = min(D[c], t + T)`。
   - 开放聚合用现有的 12 片轮转更新，接受最多 12 个月的滞后，不为此新增全图遍历。
4. **开始退潮。** 当 t ≥ D[c] 时开始退潮，替代原 `t ≥ join + hold_T`。退潮之后的行为（S 衰减、κ 定格、拒收输入、不入队）不变。
5. **开波续期**（替代 `structural.py:410-411`）。对每个现存国家：
   - 若已在退潮或已定格：先把非习俗区地点的有效值物化，再 `D = −1`，清除退潮和定格标记，S = 1，habit 恢复初值；
   - 若尚未退潮：**D 不变**（不再按「是否在本波开始后加入」决定是否重置）。
6. **禁令**（替代 `structural.py:1067-1071`）。触发条件不变（D ≠ −1、未退潮、无 P3 生效）。效果：`D[c] = month + ban_hold_scale × max(0, D[c] − month)`，结果取整到月；如果结果恰为 −1，取 −2，避免与「未加入」混淆。
7. 所有原来读 `join` 或 `clock_joined` 的地方（`core.py:382,597` 被 structural 覆写的部分；`structural.py:220-223,250-252,410-411,519,1067-1071`）都改为读 D。报告中给出改后对 `join` 的全文检索结果，证明 structural 层不再有旧语义残留。
8. 导出诊断（只写入结果 JSON，不进入游戏状态）：每个国家×商品的首次接触月、全国流行月（未达到为 null）、D 的最终值、退潮开始月、定格月；每个波次的开始月、结束月和开波原因（`origin` / `contact_pair` / `ownership_pair` / `contact_success` / `ownership_success`）。

**测试**

- `test_deadline_first_touch`：首次接触后 D = t₀ + 1440。
- `test_deadline_national`：开放聚合在第 k 月达到 20，则 D = min(原 D, k + 240)，之后不再变大。
- `test_deadline_cap`：永远不全国流行，则在 t₀ + 1440 开始退潮。
- `test_deadline_renewal`：在退潮中的国家开波后 D = −1；尚未退潮的国家 D 不变。
- `test_deadline_ban_equivalence`：在旧语义下 join + hold_T = D 的情形，新旧禁令公式给出相同的退潮开始月。
- `test_zone_does_not_start_clock`：见 §3.2。
