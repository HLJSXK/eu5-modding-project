# 24 史实世界时间线：收录规则与数据格式

日期：2026-10-21。状态：**规则先行**。本文先写定收录规则与数据格式，然后才开始编纂事实。用户决定覆盖范围为「结构层＋联姻外交」。

数据交付到 `tools/obsession_sim/world_facts_v2.json`，用来替换 `world_facts.json`。替换前，实现者要先按第 6 节补上代码支持。

## 0. 为什么要有收录规则

审计方（我）已经看过上一轮各地区的结果，知道哪些地区偏晚。如果靠手挑事实来补，很容易「看哪里晚就补哪里」，这正是 17 批评过的定年输入。因此：

1. 规则在编纂之前写定。规则不提任何商品、里程碑或地区的到达情况。
2. 编纂交给不读结果的子代理执行。他们只拿到本文、地图键表和校验脚本，不接触 09、15、20–23、`regional_targets.json` 和任何运行结果。
3. 凡符合规则的事实都要收录，不论它对传播是有利还是有害。不符合规则的一律不收，哪怕它能让某个里程碑变准。
4. 看过模拟结果后，不得增删事实。规则本身如需修订，单列修订原因，然后整体重新编纂受影响的类别。

## 1. 收录规则

时间范围为 1337 年 1 月 1 日到 1837 年。所有事实都与商品无关，`goods` 一律写 `"all"`。19 §2 的「跨商品复用」由「规则不涉及商品」来保证，不再逐条列商品。

### T 领土与国家

| 规则 | 收录 | 不收录 |
|---|---|---|
| T1 主权转移 | 1337–1836 年间某地被另一政权**直接统治**，持续 ≥ 10 年，且满足其一：覆盖某个 EU5 area 的过半地点；涉及某国首都；涉及海外据点（要塞、商站或定居点，有主权） | 朝贡、藩属、保护国（另有直接行政者除外）；短于 10 年的占领；争议性名义宣称 |
| T2 共主邦联 | 满足其一即按领土归并：两国正式合并；或者附属一方连续 ≥ 50 年没有本国常驻君主（例：阿拉贡并入卡斯蒂利亚、1603 年后的苏格兰、1580–1640 年的葡萄牙、丹麦–挪威） | 君主各自常驻的联合 |
| T3 新政权 | 新国家建立（外来征服者建国、分裂独立、殖民地独立）且持续 ≥ 10 年时，写 `formation` | 同一国家内部改朝换代，只写首都迁移（例：伊朗萨法维→阿夫沙尔→赞德→恰加尔视为同一国家） |
| T4 首都 | 第 1、3 条涉及国家的首都迁移，持续 ≥ 10 年 | 宫廷临时驻跸 |
| T5 国教 | 上述国家官方宗教或教派改变，持续 ≥ 20 年（例：宗教改革国家、萨法维 1501 年定什叶派） | 民间改宗 |

关于 T1 的粒度：EU5 地点与历史边界不会完全重合，按「area 过半地点」近似。一个 area 只有部分被占时，用 `province` 列表或 `exclude_locations` 精确划定。

### R 外国商人常驻

R1：在**另一主权**的城市中，得到制度性承认的外国商人社区，例如领事馆、商站（factory/feitoria）、商馆（fondaco/kontor）、特许居留区或条约口岸居留。商人可以是任何国籍（欧洲、亚洲、非洲都算），连续存在 ≥ 10 年。

- 主权归属：商人的母国，即其君主所在的国家，用其母城表示。没有国家的离散社群（如古吉拉特商人）以其母港当时的统治者为准。
- 不收录：没有制度性承认的散居社群；东道国本国臣民的社区（例：新朱利法的亚美尼亚人）。
- 如果东道城市后来归入商人母国，常驻在当年结束，此后由领土规则接管。

### M 王室联姻

M1：下列君主国的**在位君主**（或日后在位的王储，从结婚之日算起），与**另一主权国家统治家族**的成员（在位君主或主权诸侯的女儿、姐妹，或其本人）缔结的婚姻。联系从结婚年起，到任一方死亡为止。

君主国名单：

- 欧洲：英格兰/大不列颠、苏格兰（至 1603）、法国、卡斯蒂利亚/西班牙、阿拉贡（至 1516）、葡萄牙、纳瓦拉（至 1589）、神圣罗马皇帝/奥地利哈布斯堡、波希米亚（至 1526）、匈牙利（至 1526）、波兰（含波兰–立陶宛）、丹麦（含丹麦–挪威）、瑞典、那不勒斯/两西西里、萨伏依–撒丁（1720 起）、普鲁士（1701 起）、莫斯科大公国/俄国。
- 其他：奥斯曼苏丹，莫卧儿皇帝。

记录方式：`other` 是配偶婚前所属的国家；该国在时间线中必须存在（1337 年标签或 `formation`）。

### D 外交

| 规则 | 收录 |
|---|---|
| D1 跨文明常驻使节 | 常驻使节、使馆或宗教使团连续 ≥ 5 年，且派出国与接受国至少一方不属于拉丁基督教欧洲。例：威尼斯驻君士坦丁堡的 bailo、法国驻奥斯曼大使、俄国驻北京传教团 |
| D2 欧洲常驻使节网 | 拉丁基督教国家之间常驻大使已成惯例的时段，写成 `diplomacy_network`（成员名单与起始年），不逐对列出 |

一次性的使团、朝贡使、礼物交换都不收。

## 2. 证据级别（沿用 19 §2.1）

| 级别 | 要求 |
|---|---|
| W-A | 年份、行为者、地点明确，有机构或学术来源，学界无争议 |
| W-B | 可靠综述来源，但年份只能定到约十年，或有两种常见说法；年份写成区间 `[lo, hi]` |
| W-C | 推断。正式计分时剔除，只用于敏感性分析 |

来源必须是机构或学术网页，或者学术著作（需写章节）。可接受：大学、国家档案馆、博物馆、UNESCO、Encyclopaedia Iranica、大英百科、Oxford Reference、学术期刊。维基百科不能作为唯一来源。每条至少一个可访问的 URL。

## 3. 数据格式

文件格式为 `{"version": ..., "facts": [ ... ]}`，每条事实包含以下公共字段：

| 字段 | 说明 |
|---|---|
| `id` | 唯一，分组前缀加蛇形命名 |
| `kind` | 见下表 |
| `fact` | 一句话描述，不得出现任何消费或痴迷结果 |
| `start` / `end` | 年份或 `[lo, hi]`。延续到时间线末尾的写 1837 |
| `grade` | W-A / W-B / W-C |
| `source` | 文字出处加 URL |
| `goods` | 固定写 `"all"` |
| 行为者 | 三选一：`actor_location`（取该地点**在事实生效时**的所有者）、`actor_tag`（1337 年标签）、`actor_country`（`formation` 的 key） |

| kind | 额外字段 | 语义 |
|---|---|---|
| `formation` | `country`: {`key`（F_ 开头）, `name`, `capital`, `culture`, `religion`} | 在 `start` 建国，`end` 灭亡。领土由另外的 ownership 事实给出 |
| `ownership` | `location` | 单个地点归行为者所有 |
| `ownership_region` | `where`（`region`/`area`/`province`/`subcontinent` 及其列表）、可选 `exclude_locations`、`previous_owner_tags` | 范围内地点归行为者所有。给了 `previous_owner_tags` 时，只取当时属于这些国家的地点 |
| `capital` | `new_capital` | 行为者迁都 |
| `state_religion` | `religion`（游戏宗教键） | 国家官方宗教改变 |
| `residency` | `location`（东道城市） | 行为者的商人常驻在该城市所在的市场 |
| `marriage` | 另一方三选一：`other_location`/`other_tag`/`other_country` | 联系 |
| `diplomacy` | 同上（`actor` 为派出国，`other` 为接受国） | 联系 |
| `diplomacy_network` | `members`：成员列表，每项为一个行为者字段 | 成员两两之间形成联系 |

### 计算语义

- 每个月从 1337 年开局状态出发，把当月有效的领土事实按 `start` 先后依次套上，后套的覆盖先套的。某条事实到 `end` 失效后，该地回到「其余仍有效事实」给出的状态；没有的话就回到 1337 年的所有者。所以每条领土事实的 `end` 必须是该行为者**失去**它的年份；接手者必须另有一条事实。
- `actor_location` 按「当时」解析：套用前面的事实之后，那个地点归谁，行为者就是谁。例如 `actor_location: "bursa"` 在 1337 年指奥斯曼；1453 年之后可以写 `constantinople`。
- 国家只要失去首都所在地点就不再有首都，事实应当同时写迁都。

## 6. 实现者需要的代码支持（写进 23）

1. 三种行为者字段的解析；`formation` 新建国家，包括国家索引、首都、文化、宗教。
2. `capital`、`state_religion` 两种 kind。
3. `marriage`、`diplomacy`、`diplomacy_network` 转成 links，按 `start`/`end` 启停。
4. `previous_owner_tags` 支持列表，并可引用 formation key。
5. `goods: "all"` 的处理；删除六商品样板。
6. 每条事实加载后报告它实际影响了多少地点。影响 0 个地点的事实必须报错，不能静默跳过。
