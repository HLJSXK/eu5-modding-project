痴迷系统的计算流程与复杂度

整合 2026-10-19 的现行方案：单变量 x、方案A队列、δ = 0.1、国家级时钟退潮（T = 240），以及原计划中仍有效的部分（排期、事件、行动、风尚、国家需求接入）。设计与离线实验阶段，没有玩法代码，也未经实机性能验收。

x[v,g] ← clamp( ρ·x[v,g] + Σu→v puv·x[u,g] + hub[v,g], 0, 100 )
x 每个地点×商品唯一的持久浮点，0–100；阶段 1/20/45/70 由它直接派生
ρ、p 商品、国家政策、走廊、亲和共享参数；任务内即时求值，不落地存
hub 有限入口（港口、首都、市场中心、事件目标）的当轮输入
原地异步 读当前已提交的邻居 x，立即写回；没有 x_next 双缓冲
δ = 0.1 变化不超过 0.1 不写回、不入队，地点休眠
16 + 9d U / 节点任务预扣
方案A（侵入式队列）下的完整预扣，d=6 时 70 U；增长期实际平均约 50 U，因为大多数邻居已在排队、只读一次。现行国家时钟模式下每次服务还要查所有者是否在退潮、读邻居的 S_c，预扣变为 20 + 13d（d=6 时 98 U）。U 是离线抽象计数，调度只用变量读写，已不含原生集合成本；作用域切换和真实脚本展开仍是 P0。

原计划与现行方案的差异

删掉的东西决定了复杂度的形态：地点上没有任何缓存，所以每次服务都要重新读取全部邻边，节点能否休眠只取决于 x 这一次有没有变。

月度计算流程

调度采用方案A（侵入式队列）。一个月内按下面的顺序执行。条形图是右侧估算器在当前假设下各步每月占用的 U，改参数会实时更新；斜纹条表示不计入 50 万预算、需要另测的部分。

共享调度层 地点更新层 国家与经济层 界面层（另测）
  1. S1
    波次门控每月一次O(L)

    只遍历活跃传播注册表（L 层，短波峰值 11/12），检查日历窗口、共享阶段、截止日和通用风尚名额。约 50 个局势键中休眠的不参与。

  2. S2
    入口播种与路线登记事件、行动、风尚成立、新路线开启时O(E·(1+d))

    效果只改有界入口的 x（如 x = max(x,25)），再把该入口和它的出边目标登记进候选。来源 x 已稳定、播种没改变数值时，新路线目标也必须显式登记。

  3. S3
    共享输入变化唤醒政策、禁令、所有权、市场迁移、供货变化O(W·nc)

    国家政策改变 p/ρ 后，该国所有 x > 0 的地点都可能需要重算，按 nc 分片登记。有 hook（如所有权变化 on_action）就逐项登记；没有 hook 的变化只能用有界轮转探测，发现延迟单独报告。

  4. S3b
    国家时钟每月，对已加入未结束的国家O(Cclk) + 重标定 O(nc)/114 月

    到期（加入月份 + T）的国家进入退潮；退潮中的国家 S_c ← 0.98·S_c。S_c 跌破 0.1 时遍历本国地点写回一次（有习俗保留率 κ 时在 0.01 以下定格）。退潮中的地点不再服务、不接收输入，读取一律用 x × S_c。

  5. S4
    节点服务每个逻辑轮，队列跨月续跑Θ(Σv∈A(1+dv))

    轮开始时记 round_remaining = length，逐个预扣完整任务费用后出队、执行公式并原地写回。x 变了就把自身和出边目标入队，已在排队的目标只读一次 q 就跳过；没变就不入队。新入队的排在本轮之后，本轮不递归。额度不够时停止出队，下个月继续，此时传播按日历变慢。

    • p 的即时求值（亲和、政策、走廊、供货）按目标节点一次、按边一次分开计费
  6. S5
    轮次交接round_remaining 归零时O(1)

    方案A下没有集合交换：round_remaining 归零即一轮结束，下一轮开始时重新读 length。只是几个商品级变量的读写。

  7. S6
    国家聚合节点变化时增量，权重或所有权变时重建O(f·|A|) + O(R·nc)

    任务内用临时 old/new 给国家 X 和成员计数做差值（跨过 x = 1 时成员计数 ±1）。人口权重或所有者变化后差值不再可靠，就把该国×商品置脏，分片读取当前 x 重建，不保存逐地点旧贡献。

  8. S7
    经济提交SOL 原有自然入口：玩家月度、AI 年度O(P·Gc) + O(Cm·Gc/12)

    读取已准备好的 X 快照，算 H = 1 + h·X/100，按 B×H×M 换算成痴迷修正与替代修正的 size 写入，再走原有替代计算和 SOL 求解。求解本身不是新增成本；聚合未完成时沿用旧快照。

  9. S8
    事件与 AI 行动成员国家月度脉冲，AI 行动 90–180 天一次O(Cm) + O(Cm·K/90d)

    冷却（同局势 12 月、同国 5 月）先过滤，条件只读国家聚合。命中的效果回到 S2 或改共享参数回到 S3，不在这里直接扫描地点。

  10. S9
    波次交接与清理截止日后分片，摊到每月O(length)

    截止后停止新的传播登记，残留队列分片出队清理，每个 3 U。已加入的国家继续按 S3b 的时钟退潮，直到归零或定格为习俗，这部分不再服务节点。

  11. UI
    地图与面板玩家打开时M1：O(N) 每次重绘

    M1/M5 每地点读一个 x 比较阈值；M2/M3 读国家聚合；面板成员排名取前 8 名为 O(Cm)。只读也有成本，但由引擎渲染节奏决定，需要单独实测，不放进 50 万。

一次节点任务的成本拆解

与方案A参考实现 queue_pointer_scheduler.py 的预扣函数逐项对应。预扣按最坏情况（x 发生变化）收取，执行后实际花费 ≤ 预扣。

# 预扣 3 + 8 + 4·d_in + 1 + d_out + 4·(1+d_out)，额度不足则不出队
v = pop()                          3  读 head、读 head.q、删除 q
old = x[v]                         1  读自身
y   = ρ · old                      1  保留乘法
for u in in_edges(v):              每条入边 4：
    y += p[u,v] · x[u]             4  枚举 + 读邻居 + 乘 + 加
y   = clamp(y, 0, 100)             2  两次比较
if y < ε: y = 0                    1
x[v] = y                           1  写回
changed = |y − old| > δ         1  δ = 0.1；未变化则不写回
                                   1  轮内计数 −1
if changed:                        1  自身登记
    push(v)                        4  刚出队，必为新入队
    for w in out_edges(v):         每条出边 1 + push：
        push(w)                    1+4 新入队；已在排队只读 q：1+1
出队 + 固定部分11
入边 4 × d24
变化时自身登记与入队5
出边最坏 5 × d30
预扣（d = 6）70
未变化时实际35
变化、邻居都已在排队52

网格实验里 88% 的服务有变化，邻居入队尝试中 97.7% 已在排队，所以实际平均约 50 U，远低于预扣上限。没有计入：p 的即时求值（估算器里单列）和作用域切换。所有调度操作都是常数次变量读写，不随队列长度变化。

活跃集与退潮方式

S4 的总量等于活跃集大小乘单节点成本。增长期内部会被夹到 100 而休眠，只有一条前沿带活跃；退潮期如果逐节点计算，整片已触及区域每月都在变，成本会暴涨。现行方案把退潮交给国家时钟，节点服务只剩增长前沿。

由此得出的结论

退潮交给国家时钟后，节点服务只剩增长前沿

逐节点退潮时，全图一轮约 70 万 U，大于 48 万的总额度，而且 δ = 0.1 下会冻结。国家时钟把退潮变成每国每月约 3 U 的共享因子更新，外加约每 114 个月一次的本国重标定。合成网格上基准情景单商品平均约 2.75 万 U/月，峰值 12.2 万 U 出现在增长前沿最宽的时候，与退潮无关。

δ = 0.1 与国家时钟一起采纳

共享变化容差 δ = 0.1（02 第 2.1 节）让增长期总 U −51%、强控制边界 −82%，前沿慢约 15%。它会让逐节点衰退停在 δ/(1−G)（各商品 2–50，都高于成员门槛 1），所以退潮不走逐节点衰退，而由国家时钟承担（02 第 8 节）。曾比较过的退潮期年度步长、较大 ε、全图共享 S 等做法保留在实验对比项和 tools/obsession_sim 预设中。

预算分配直接改变传播速度

基准情景增长前沿峰值 1,664 个排队地点、月峰值约 12.2 万 U。给单商品每月 4 万 U 的额度时，增长从 780 个月拉长到 1,132 个月（慢约 1.45 倍），全图平静从第 1,760 月推迟到第 2,568 月。所以历史校准必须在实际预算下跑（模拟包的 --budget），不能先用不限额结果校准再加上限。

方案A消除了原生容器复杂度这个最大的未知数

如果原生集合插入需要线性查重，单轮会从 Θ(d·|A|) 退化到 O(d·|A|²)。方案A改用排队期间才存在的地点指针 q，入队、出队、去重都是常数次变量读写，这个风险不复存在；同时消除了"已读到新值又被重排"的约 5.4% 空跑。剩下的 P0 是地点变量能否保存并进入地点引用。最大邻接度决定单个任务的预扣上限；长程贸易、宫廷入口如果做成高扇出边，应当限定为有限入口而不是普通邻边。

稳定的部分确实是便宜的

无关连通分量从不登记；增长期饱和区夹在 100 后休眠；零输入不会自热；撤掉一个来源不需要补丁。这些在小图实验中都已断言通过，说明稀疏候选在增长期是有效的，风险集中在退潮期和大范围政策唤醒。
