# SOL 联机不同步诊断

这套工具用于定位 SOL 的执行顺序或缓存差异，不宣称已经修复不同步。
普通源码默认关闭诊断。诊断包只增加文件日志和执行期间的命名作用域，
不写诊断用游戏变量、不使用随机调用、不改变经济公式，也没有修改初始化主机判断。
日志仍有执行开销，可能影响复现时机，故必须保留关闭日志的对照测试。

## 测试包

开发者在仓库根目录运行（Python 需安装项目生成器依赖 PyYAML）：

```powershell
& $env:EU5_PYTHON scripts/sol_oos.py build --target stable --trace --output dist/sol-oos-stable-trace
# 独立版使用 --target sol_standalone，不能与常规版同时启用。
# 对照包使用新的输出目录并省略 --trace。
```

命令生成目录和同名 ZIP，其中 `mod/` 是完整的所选 SOL 模组内容。
两台机器使用同一个 ZIP，分别将该目录作为测试模组安装并由启动器启用；
保留其原有模组 ID，不要同时启用创意工坊原版、普通本地版和诊断版。
常规版仍需相同版本的 CMF；本工具不打包 CMF 或其他模组。
请在游戏/启动器中确认实际启用的是这份目录，且其他模组、加载顺序、
游戏版本、校验码、语言和设置均一致。`sol_oos_build.json` 记录文件哈希；
收集器会重新读取指定目录计算哈希，但不能自动证明游戏加载了该目录。

先用无关的新测试存档进行短测，再用相同的出错前存档复现：

1. 保留原有日志后重新启动双方游戏，使本次日志只包含一次测试。
2. 检查文件日志中是否出现 `SOL_OOS|1|gui_init_begin` 和配对的结束标记。
   若没有输出，先核对实际加载目录、包中的诊断开关及游戏日志/调试启动设置。
   若需要启用调试启动参数，两端必须一致并重新核对校验码。没有标记不算通过。
3. 确认国家标签、游戏日期与屏幕一致；数值必须与存档或其他可靠读数核对。
   现有知识库明确提醒过动态 `debug_log` 读数不可靠，未经验证不能将数值差异
   当作求解器错误，也不能将相同日志当作同步证明。
4. 至少跨过一次月度经济刷新，记录首次 OOS 的游戏日期、类别和发生前操作。
5. 保留双方 OOS 报告、文件日志、出错前存档。日志写完后再收集；不要重启游戏
   覆盖本轮日志。若必须退出才能刷新文件，先保存 OOS 目录并正常退出到桌面。

## 收集（联机伙伴不需要安装 Python）

Windows PowerShell 5.1 或 PowerShell 7 均可。解压测试包后运行其中的脚本。
以下路径仅为示例，`-ModPath` 必须是游戏实际加载的 SOL 根目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\collect_sol_oos.ps1 `
  -Role host -Session sol-test-01 `
  -ModPath 'D:\EU5-test\SOL' `
  -GameVersion '填写完整游戏版本' -GameChecksum '填写校验码' -Language simp_chinese `
  -Notes '填写其他模组、加载顺序、设置、OOS 日期和类别'
```

客户端同样运行，将 `-Role host` 改为 `-Role client`，`-Session` 保持一致。
`-ExecutionPolicy Bypass` 仅针对这次进程，不修改系统策略。

默认用户数据目录来自 Windows“文档”位置下的
`Paradox Interactive\Europa Universalis V`。若实际位置不同，显式传入
`-UserDataPath '实际目录'`。脚本复制该目录的 `logs/` 和 `oos/`；缺失、
复制失败或跳过链接都会在报告中提示。默认复制现有全部 OOS 事件，可能较大；
其中较早的事件要按此次日期/事件编号另行筛选，比较器不会自动分析它们。

可用 `-SaveFile '出错前存档路径'` 显式附带存档，用 `-ExtraFile` 附带加载列表、
设置或截图文件；这些参数支持多个文件。默认不收集存档，不访问游戏程序内存，
不安装驱动，也不会上传任何文件。报告会包含路径、日志和玩家相关信息，分享前可检查。
`-OutputRoot` 可指定输出位置，必须在游戏数据目录和模组目录之外。

将双方生成的 ZIP 一起交给开发者。原始日志、存档和报告均不会被修改或删除。

## 对比（开发者）

```powershell
& $env:EU5_PYTHON scripts/sol_oos.py compare host-report.zip client-report.zip --output comparison.json
```

比较器只需 Python 标准库，可以读取 ZIP 或解压目录，无需解压 ZIP 到磁盘。
报告包含双方 SOL 文件差异、采集完整性提示、各阶段调用次数、
日志序列中第一次观察到的不同记录，以及按游戏日期/国家分组的差异。
不会按本机时钟比较，不会把不同文件里的日志拼成虚假的跨文件执行顺序；
OOS 目录中的旧日志不重复计入本次文件日志。

记录格式为 `SOL_OOS|1|阶段|国家标签或GLOBAL|游戏日期|event或指标值`。
日期文本受语言影响，因此双方必须使用相同语言。
仅记录人类国家的求解、修正应用与完整刷新，以及全局市场/世界刷新和 GUI 入口；
不遍历额外领土，不记录每个地点/商品，不覆盖所有 AI 状态。
`MISSING` 表示变量不存在，和数值零不同。第一版缓存读数包括求解状态、
采用策略、基础支出总量和生活水平。它们不是完整的求解输入或游戏状态校验和。

## 如何解释结果

- 双方模组文件不一致：先统一测试包，不能据此推断算法有问题。
- 没有诊断记录、记录未展开、日志不完整：修复采集/日志条件再测试。
- GUI 初始化重复：核对调用次数与各端顺序；它是线索，不自动等于 OOS 根因。
- 同阶段同国家的缓存不同：结合此前输入和 OOS 数据继续细分，不直接认定该阶段是根因。
- 日志相同：仅说明已记录部分一致，仍需检查 OOS 数据和未记录的国家/地点。

先测原始行为，再以单独补丁验证初始化主机来源限制；避免把行为修复和诊断一起引入。
后续扩展日志时仍须遵守共享参考政策和生成源所有权。
