# EU5 Mod - Project Overview

> This document is maintained by AI. Update it whenever mod features or directory structure change.
> Last updated: 2026-10-23

## Project Identity

- Mod name: **Standard of Living (SOL)**
- Mod ID: `hades.sol` | Version: `261013` | Target: EU5 `1.4.*` beta
- Release versions use `YYMMDD`; `build.bat` stamps the selected target from the local date while `supported_game_version` remains independent
- Requires Community Mod Framework v2.*; SOL owns a unified Glorp UI-based location window rather than declaring Glorp UI or Construction Manager as metadata dependencies. The copied file retains optional `cm_*` references so Construction Manager can supply its definitions when enabled.
- Active deploy targets: `src/stable/`, `src/sol_standalone/`, `src/sol_pp_compatibility_submod/`, `src/sol_mnt_compatibility_submod/`, and `src/sol_jtg_compatibility_submod/`

## Branch Boundary (2026-08-09)

`main` is the reference for the shipped location-level income=expense system:
one monthly pass computes each location's raw coefficient, applies the legacy
country poverty factor, and writes the location modifier. It has no country
matrix or KKT solver. `beta` is a development branch for the not-yet-shipped
country-level system. Its country classifier, matrix aggregation, exact
diagnostic, prefilters, approximation candidates, gate, and final coefficient
application are beta-only work and must not be described as part of the stable
location-level algorithm. The four-way equal-capacity (`country_total / 4`)
classifier is retired; the beta classifier uses a 1% per-class anchor and
negative-pressure capacity allocation instead. See
`docs/technical/SOL_Country_Level_Strata_Demand_Model.md` for the module and
performance boundary.

## Core Features

1. **Standard of Living (SOL) System** *(primary feature)* - Recalibrates baseline `demand_add` for 56 goods in `z_SOL_pop_goods.txt` and includes the 1.4 `camels` good in market accounting, disables the engine-wide development demand multiplier, fully negates all nine vanilla per-good development thresholds, and sets `NPop.POP_NEEDS_INCOME_SCALE = 1` so strata pay the nominal cost of purchased goods instead of vanilla's 33% surcharge. It applies a monthly country-closed `local_pop_demand` coefficient after raw location spending, class assignment, and matrix aggregation. The CMF Performance tab's Country-level Solver group independently controls the exact solve and the approximation solve for each of AI and human countries; all four default ON. A side whose two toggles are both off skips country-level aggregation entirely and uses a raw-only baseline that omits classification, ordering, matrix construction, approximation prefiltering, solver bookkeeping, and human solver logs while preserving raw location demand and modifier writes. Approximate candidates are accepted only when neither scaled metric worsens against raw; otherwise `raw_fallback` preserves raw factors. Locations are classified by nobles, clergy, burghers, or lower-strata relative over-representation, with lower = commoners + tribesmen; class matrices remain raw-weighted so within-class local variation is preserved. The CMF in-game log is deliberately minimal: one human-only row per country solve naming the adopted strategy (exact, strict no-worsen vertex sweep, or raw fallback), with no dynamic values and no per-class/matrix/candidate rows. The system feeds the Living Standard situation panel, map data, mapmode, and location GUI.

**Country-level nonnegative demand approximation** - A size prefilter in `sol_solve_country_pop_demand` routes any country with `num_locations < 5` straight to the raw-only path, skipping classification and the solver entirely; below four locations the pigeonhole principle caps the matrix at three non-empty columns, and measured gains are marginal (median scaled L1 for a single-location country moves 0.329 to 0.310, versus 0.371 to 0.222 from three locations up), so skipping them drops 70% of the exact-failed country count for 17% of the owned-location traversal. It is checked before anything else because `num_locations` is known up front while the non-empty class count only exists after the confidence-ordered classification pass has been paid for. Past that gate, stable and standalone enter the country solver body only when the matching CMF preparation toggle is enabled. Inside that dependency, exact runs first when enabled; exact success is adopted directly as strategy id 7. Exact failures run a single strict no-worsen vertex sweep (`sol_country_demand_run_vertex_selector`, strategy id 8) for both AI and human countries. The sweep minimises mean relative deviation (scaled L1 over the four stratum rows) with worst-stratum relative deviation (scaled L-infinity) as a 1% tie-break, under the hard constraint that neither metric may worsen against raw; the incumbent is seeded with raw itself so a fallback always exists. These are the only two live strategies: the four L2 variants, `minimax_ratio`, and AI `proportional_fast` are all retired. The L2 variants and minimax optimised neither declared objective and were beaten on scaled L1 in 91.1% of exact-failed countries (median +17.11pp, zero regressions); `proportional_fast` adopted a candidate for only 4.2% of eligible countries against the sweep's 90.7% on the same save, with median scaled L1 barely off raw (0.335 vs raw 0.343, sweep 0.114), so both sides were merged onto the single shared path. Vertex enumeration covers 209 (exact-row-order, free-column) combinations, which offline replay confirms matches partial pivoting exactly, and shrank the solver file by 87%. A raw-error prefilter (`sol_country_demand_gate_possible`) skips the sweep entirely when every raw row is already inside tolerance; when the sweep finds no admissible vertex, factors remain 1 and locations use `raw_fallback`. Runtime variables are limited to state needed by solving, strategy selection, and factor application; obsolete Log/offline-only best-candidate, failure-detail, final-error, candidate-count, and residual caches are not retained. Compatibility submods inherit this base effect and keep their local `REPLACE` overrides.

2. **Economic Balance & Anti-Snowballing** - Base tax efficiency defaults to -15% and is CMF-adjustable. Age escalation raises construction, RGO expansion, city/town upgrade, and food-consumption pressure across ages; by Age 6 it reaches -100% global building efficiency, +100% RGO expansion cost, +50% city/town upgrade cost, and +50% pop food consumption. Base RGO size is halved to 1, total-population RGO scaling is reduced, low-control locations receive a construction-efficiency penalty, and road prices are increased to gravel x2, paved x2, modern x3, railroad x5.

3. **Tax, Prices & Development** - Difficulty tax bonuses are halved for AI Hard/Very Hard and Player Easy/Very Easy. Diplomatic spending changes with used diplomatic capacity, cultural tradition reduces stability investment cost, and gold-transfer/action prices are rebalanced. GDP-to-development applies a yearly local development modifier scaled by local GDP, and AI countries can receive a small configurable devastation-recovery bonus.

4. **War & Combat (Harsher Wars)** - War exhaustion further reduces levy size, control, stability, legitimacy, and defensive capability. Total occupation adds +1.6 monthly war exhaustion on top of vanilla, and capital occupation adds +0.2 monthly war exhaustion on top of vanilla. The reduce-war-exhaustion cabinet action can be restricted to peacetime. Blockade, siege, occupation, hostile troops, looting, raiding, and razing modifiers are harsher for prosperity, control, construction, migration attraction, development, raw materials, and food.

5. **Food, Climate & Prosperity** - Normal winters and raised levies create harsher local food pressure, while Little Ice Age event penalties are softened to avoid runaway food-crisis spirals. Age escalation starts with mild prosperity scarcity and later returns prosperity in the late game.

6. **Colonial & Diplomatic Restrictions** - AI generally requires more than 500 tax base to create colonial charters; historical colonizers are exempt, and colonial nations can colonize only in their capital region. The player is not restricted by this rule. In the 1.4 beta reference the scripted create_colonial_charter action has disappeared; these restrictions still live in the old override and require migration/verification against the new creation path before they can be claimed to work. Asking another country to join a war costs 30 favors.

7. **CMF Settings & Migration Support** - Two CMF tabs. The Features tab registers SOL pop demand, map coloring, economic balance, base tax efficiency, age escalation, stability discount, diplomatic spending, difficulty tax nerf, GDP-to-development, AI prosperity recovery, and war acceleration sub-features. The Performance tab holds a Calculation Frequency group containing the default-on AI reduced-frequency toggle, followed by the four default-on exact/approximation toggles. Humans solve monthly. Reduced-frequency AI solves on its own yearly anniversary without monthly territory/market/goods snapshot polling or dirty-triggered solves; explicitly disabling the full mod's frequency toggle restores monthly AI solving. Standalone uses human-monthly/AI-yearly scheduling without CMF. Both targets still apply the one-month location modifier every month. New countries without a solve status initialize once; an acquired/settled location with no cached modifier size gets neutral size 0 inside the existing apply traversal and waits for the next scheduled solve, while existing coefficients are preserved. Start/load and explicit SOL/substitution setting callbacks retain their immediate refresh/cleanup behavior; ordinary AI economic and ownership changes deliberately wait for its anniversary. Built-in after-lobby migration logic notifies human players when loading older saves.

8. **Prosper or Perish Compact Compatibility Submod** - A separate final-loading target keeps full PP while narrowing full SOL to its income-based demand/UI, compact age construction and city/town costs, low-control construction penalty, base tax/diplomatic/stability rules, difficulty tax adjustments, configurable AI devastation recovery, non-conflicting prices, and selected war/expansion rules. It removes SOL residuals from PP-owned weather, Little Ice Age, base location, blockade, siege, occupation, and looting values; lets PP's later same-operation price file naturally replace SOL's repeated road-price fields; keeps SOL GDP-to-development disabled by default but exposes a compatibility-specific CMF opt-in; excludes non-compact age fields; preserves PP's zero lumber demand; and adds PP `victuals` to SOL calculations and both goods panels. Compatibility `demand_add` sets rounded Compact `victuals` net-demand targets of 0.05/0.015/0.035/0.0004/0.0002/0.0004 for nobles/clergy/burghers/laborers/peasants/soldiers, chosen from the PP-only spending-ratio comparison. Stable and standalone contain no PP-load detection or PP-only UI/value data.

9. **Just Trade Goods Compact Compatibility Submod** - A separate final-loading target applies SOL-style per-stratum scaling to the 26 direct-demand goods from Just Goods, including the clocks goods added by the merged release. The fixed multipliers are 1.05/0.45/1.75/0.02/0.10/0.025/0 for nobles/clergy/burghers/laborers/peasants/soldiers/tribesmen; scaled targets use clean 0.01/0.001/0.0001/0.00001 steps by magnitude, all 26 source wealth gates, all 15 source development gates, and all recorded continent/sub-continent demand modifiers are fully negated, and slave demand remains unchanged. It adds final JTG quantities to SOL market and country accounting and rebuilds both goods panels with all 82 demand goods using the JTG DDS icons. The merged Just Goods mod is required, and this target is mutually exclusive with the SOL-PP compatibility target because both replace the same two SOL effects.

10. **MEIOU and Taxes Compatibility Submod** - A separate final-loading target makes M&T authoritative for economic balance by default while retaining SOL demand, Living Standard UI/map, migration, and non-conflicting war/colonial rules. It rebuilds all 56 SOL goods from complete M&T objects where available and current vanilla fallback objects for new goods such as camels, inversely scales the seven SOL pop quantities against M&T prices, equalizes maize/millet/rice, keeps tools laborer demand at 0.0005, preserves M&T slave demand, and removes wealth/development gates. Its marked EPBM replacement leaves M&T country charges unchanged while caching attributable domestic maintenance on SOL's five location variables; foreign, crown, dhimmi, and Gaelic-tribes attribution is excluded by policy. A compatibility-specific CMF economic master defaults off and can explicitly re-enable SOL's trigger-gated base-tax, age-escalation, stability, diplomatic-spending, difficulty, GDP-to-development, and AI-recovery settings; dynamic values and callbacks remain available for that opt-in, while M&T continues to own goods, prices, and economic static modifiers.

11. **Unified Glorp UI Location Window** - Full SOL uses the complete current Glorp UI location-window file as its merge base, preserves its 1.4 action-button and road-builder APIs (and migrates older snapshots when needed), preserves Glorp UI and optional Construction Manager references, and inserts one Living Standard tooltip button. SOL Standalone remains vanilla-based, and the M&T target migrates its own final window. Missing `cm_*` definitions with SOL alone are expected optional-dependency logs; enabling Construction Manager supplies them without changing the unified file.

12. **Unified SOL Economy UI** - The location tooltip and country panel use sheet C purchasing-power rows: a centred signed -100%..+200% bar uses separate linear scales on either side of the 0% baseline, alongside right-aligned unclamped raw alpha-minus-one percentages and a smaller gray funds / baseline pair with bilingual explanatory hover. One shared ruler above the estate rows shows equidistant -100%, -50%, 0%, +100%, and +200% labels; each row retains short ticks and a thicker fixed zero line. Zero funds reaches -100%; three times baseline reaches +200%. The total row has a faint gold background and outline with a thicker bar; five compact 42-unit estate rows use subdued backgrounds and smaller percentages; dials, population/income distribution charts, share tracks and ratios are temporarily removed by user decision. Solver beta is absent from SOL GUI; the location modifier retains the applied result. Goods retain F's required/daily/luxury tiers and all 67 memberships across 20 groups, with fixed cards, supplied/total counts, gold supply ratios, mutually exclusive full/dim goods images and a seven-level native substitution-icon row beneath each grouped good. PP/JTG regenerate the same shared layout with neutral extra goods; M&T inherits the base UI. Basket-cell hover retains country/owner lifecycle and location-price context. Actual goods tooltips use sheet C tier/group rows with every member's icon/name and seven price preferences; only market goods tooltips add the current market/base-price ratio and a gold highlight for the current tier. Ungrouped, unknown/default and empty goods keys hide the substitution section. All vanilla statistics are preserved.

13. **Country goods substitution** - Algorithm A with price-only preferences retains 20 groups, 56 core goods and 67 overlapping memberships. Explicit seven-stratum subscriptions in `pop_group_baskets.csv` require whole groups, with positive calibrated quantities for every subscribed member and no demand outside the subscribed union; generators fail on incomplete baskets. Baskets evaluate once per country market/pop type after aggregating owned population, and overlaps include only subscribed groups; seven country-adjusted market spending totals feed each location and the existing SOL solver. Permanent country goods modifiers update only when changed or missing. The default-on CMF switch cleans modifiers and caches when disabled; standalone enables substitution without CMF. PP uniformly removes lumber from groups and keeps victuals neutral, M&T preserves positive member demand after price scaling, and the 26 JTG extras remain neutral. Source generation and offline regressions cover whole-group consumption and commoner condiments; EU5 demand refresh, fixed-point rounding, slave effects and actual month timing still require in-game acceptance.

14. **Living Standard four-section left-panel HUD** - Stable and standalone ship a 570×36 row below the nine left-panel buttons, split into income/YoY, purchasing power, spending/substitution, and world-ranking sections with independent contextual tooltips. Current income remains available on the first solve while YoY waits for a same-month prior-year baseline; the ranking tooltip also exposes generated per-estate world rank, percentile, count, and top-country caches. The spending section is gated pending a country-side per-good spending cache and uses static goods branches because GUI variable-to-Goods promotion is invalid at runtime. An independent Glorp UI shim shifts its own stats bar and collapse toggle down one row; offline rendering covers both languages, pending/ranking states, and Glorp UI, while in-game hover, click pass-through, scaling, and actual load order remain to be confirmed.

15. **SOL map modes and HUD navigation** - The four HUD sections preview their corresponding map on hover and select it on left click: local savings-adjusted per-capita income, local raw purchasing power, country goods substitution in each country's own color, and overall world ranking from red to green. Country map tooltips reuse sections three/four with a preserved hovered-country scope, including translated summary bindings and nested ranking peers; the two local maps are independent of the country solver's applied modifier. Both targets ship the map menu icons and bilingual labels. Offline scope tests and renders cover the bindings; engine hover, selection and country aggregation still need in-game acceptance.

## SOL System Architecture

- **Calibrated demand baseline** - `data/target_demand.csv` drives `src/stable/in_game/common/goods/z_SOL_pop_goods.txt` and `src/sol_standalone/in_game/common/goods/z_SOL_pop_goods.txt`. These `demand_add` values remain the baseline that the SOL multiplier scales. The generator rejects unnegated vanilla wealth-threshold keys (including the 1.4 wine gate) and requires exact negation of every vanilla `development_threshold`, while both targets set `NPop.DEVELOPMENT_SCALE_ON_DEMAND = 0` and `NPop.POP_NEEDS_INCOME_SCALE = 1`; the latter removes vanilla's 33% purchase-side surcharge so nominal goods cost matches SOL's strata-income accounting.
- **Hardcoded unit consumption constants** - `data/demand_price_table.csv` is converted into each target's `in_game/common/script_values/SOL_market_unit_consumption_values.txt`, storing net demand quantity for each pop type and good. Duplicate goods that appear in multiple old demand groups are counted once.
- **PP compatibility calculation** - The compatibility target uses fixed rounded `victuals` net-demand targets of 0.05/0.015/0.035/0.0004/0.0002/0.0004 for nobles/clergy/burghers/laborers/peasants/soldiers, selected after comparing each stratum's PP-only default-price spending ratio against six staple goods. It injects the positive or negative `demand_add` delta needed to reach those targets, and the same final quantities feed SOL accounting. It negates PP's `victuals` development threshold, forces all lumber quantities to zero, and explicitly `REPLACE`s the two SOL effects that need PP-aware market refresh and country goods aggregation. Existing SOL values/effects remain owned by the full SOL mod instead of being duplicated under later filenames. The compatibility-specific `sol__pp_gdp_dev` CMF setting defaults off, has no no-CMF fallback, and can explicitly restore SOL's yearly GDP-to-development pulse.
- **M&T compatibility calculation** - The M&T target uses complete M&T goods bodies where available and current vanilla fallback for new goods such as camels; it replaces population-demand fields and rebases lumber location_potential because its old vanilla trigger was removed. Valid M&T inverse_control military penalties remain intact even though vanilla dropped them from that object. Seven SOL quantities are inversely scaled by the vanilla/SOL to M&T default-price ratio and rounded to five decimals; maize, millet, and rice are equalized from combined SOL spending, tools laborer demand resolves to 0.0005, M&T slave quantities remain intact, and all wealth/development gates are removed. Matching generated constants and market refresh logic keep SOL accounting aligned with the final goods database. The compatibility-specific `sol__mnt_as_on` CMF master defaults off and gates the restored SOL economic subsettings; without CMF the trigger stays false, while an explicit opt-in reactivates only trigger-controlled SOL systems and leaves M&T's unconditional goods, price, and static-modifier authority intact.
- **JTG compatibility calculation** - `data/jtg_pop_demand.csv` records the 26 direct-demand Just Goods goods plus their source wealth/development gates and continent/sub-continent demand modifiers. The compatibility generator applies fixed per-stratum SOL multipliers, rounds targets to clean 0.01/0.001/0.0001/0.00001 steps according to magnitude, injects the exact five-decimal demand deltas, fully negates every recorded threshold/modifier, and emits matching unit-consumption constants. It replaces only `sol_refresh_market_pop_demand_maps` and `gls_accumulate_panel_stats`, expands both goods grids from 56 to 82 entries, leaves six demand-free Just Goods goods and all slave demand untouched, and audits the CSV against the installed `3785316314` Workshop content root so new gates cannot be omitted silently.
- **Unified Glorp UI merge** - `sync_location_window.py` validates Workshop `3812518640` (`glorp.ui.rio`, version `04.10.26`) as the current source snapshot, uses the complete Glorp UI location window as the merge base, accepts its already-migrated 1.4 GUI API, preserves the integrated optional `cm_*` references, and inserts one SOL Living Standard tooltip button. It also keeps the extracted location types synchronized; older pre-1.4 snapshots remain supported by the shared migration helper. The M&T generator applies the same migration to its own reference snapshot.
- **Generated economy effects** - `gen_sol_economy_effects.py` makes both base-target `A_SOL_economy_effects.txt` files and matching `B_SOL_country_demand_solver.txt` files. A owns location raw demand, classification, matrix aggregation, strategy logging, and modifier application; B owns the exact 4x4 solve, Gaussian elimination primitives, the 209-case vertex sweep with its scaled-L1/L-infinity metrics, the raw-error prefilter, and strategy selection. The split changes file ownership and loading size only; effect names and cross-file calls remain global and compatible submods continue to inherit the base effect.
- **Exact-solve feasibility is cone containment, not linear independence** - `M x = t` with `x >= 0` is solvable exactly when `t` lies in the nonnegative cone spanned by the four class columns. `det(M) != 0` only gives uniqueness, and a healthy condition number does not imply feasibility. Because every class column is a sum of nonnegative location vectors, `cone(any 4-way partition)` is contained in `cone(all owned locations)`, so when the target is outside the all-location cone **no classifier change, class count, capacity rule, or conditioning fix can make the exact solve feasible** - only relaxing the target definition or accepting an approximation can. Many normal save states are genuinely infeasible in this sense; measured HUN residuals were 0.0465-0.1057 with 8-43 locations requiring negative factors. A zero coefficient returned by a nonnegative approximation is a legitimate boundary optimum rather than a clamped artifact, which is why a whole class can legitimately land on `-100%`. Run `tools/eu5_save_parser/cone_feasibility.py` before diagnosing any such report; see `docs/technical/SOL_Country_Level_Strata_Demand_Model.md` section 3.9 for the derivation, the subset conflict table, and the four attributions the data ruled out.

- **Country solver runtime cost** - Measured in variable operations (see `tools/eu5_save_parser/solver_outcome_survey.py`): the raw pass is 70 per location, classification plus matrix aggregation is 37 per location, solver setup is 120 per country, the exact 4x4 solve is 112, and one vertex case is 218 so the full 209-case sweep is 45,562. Total cost is best read as `107 * total_locations + 45,562 * countries_reaching_a_sweep`, and the second term dominates: one sweep equals 426 locations of per-location work while the mean country holds only 9-33, making sweeps 87%-94% of all solver cost. So the only optimisations that matter are ones that reduce how many **countries** reach a sweep — never disabling the exact solve, which is 0.2% of cost and saves a whole sweep on every success. Countries with fewer than five owned locations pay none of the solver cost: the size prefilter routes them to raw-only before classification runs. For the rest, with `n` owned locations, classification still contributes one confidence sort `O(n log n)` plus linear scans and matrix aggregation `O(n)`. After raw-error and nonempty-column prefilters, exact-enabled countries stop at their validated 4x4 result; exact-disabled countries skip that matrix solve but still prepare approximation inputs. Approximation cost is a fixed 209-case vertex sweep, gated by the raw-error prefilter and by the side's CMF approximation toggle. Only two strategy ids are live: `7` for exact-direct and `8` for the vertex sweep, with `0` marking `raw_fallback`; the single CMF log row names the adopted one, and no separate numeric Log/offline-analysis cache is persisted.
- **Yearly market spending maps** - `sol_refresh_market_pop_demand_maps` scans `every_market_in_world`, writes consumed-good counters keyed by market scope, and caches one unit-spending `global_variable_map` per pop type. For each consumed good, spending is computed as hardcoded consumption quantity times `min(market_price(goods), default_price(goods))`, so cheaper goods lower base spending while expensive goods do not inflate it above vanilla base price.
- **Yearly SOL maintenance caches** - Normal SOL targets call `sol_update_estate_building_maintenance` to scan every owned land location, cache the five SOL estate building counts, and subtract 1 gold per cached estate building from matching stratum income. In the M&T target that scanner is disabled: M&T's own player-monthly/AI-yearly EPBM calculation writes charge-factor- and estate-power-adjusted domestic location costs into the same five variables without changing M&T country deductions.
- **Monthly local demand modifier** - `monthly_country_pulse` calls `sol_update_local_pop_demand_modifiers`, which computes each owned land location's income-closed raw coefficient, then (for countries with at least five locations) scores its four-stratum shares relative to nationwide shares and classifies it with a confidence-ordered greedy pass. Classification capacity is measured as `raw * base`: every class receives 1% of nationwide raw spending as a deliberately tiny anchor, and the remaining 96% is divided among strata with `raw baseline - target > 0` in proportion to that downward pressure. The matrix is built raw-weighted; exact is attempted first, then exact failures run the shared 209-case strict no-worsen vertex sweep for both AI and human countries. A candidate is admissible only when neither its scaled L1 nor its scaled L-infinity exceeds the raw value. A successful factor multiplies every member location's raw coefficient before the one-month modifier is applied; factor 1 preserves raw, 0 to 1 reduces it without crossing zero, and factors above 1 are uncapped. Missing classes leave empty columns; singular, negative, numerical-residual, or gate failures use `raw_fallback`. The first post-lobby refresh primes the estate-building cache once; yearly pulse keeps it current afterward.
- **Income-closed location scale** - Each location sums five gross stratum incomes, subtracts cached estate building maintenance to derive total net stratum income, applies the country's unified savings adjustment `(total savings / total savings target - 1) * 0.25` capped at `0.5` (+50%), and divides liquid funds directly by market-keyed base spending. Commoner base spending remains exact by internally using laborer, peasant, and soldier unit-spending maps. Development does not scale or gate demand. The raw result remains cached for diagnostics and fallback; successful class coefficients use dedicated caches and become final for classified locations, while negligible-base class-0 locations and failed country solves retain raw. No country-level poverty compensation factor is applied.
- **Country-level aggregation** - Location income, savings, base spending, liquid funds, solved final coefficient, and consumed market goods feed the situation panel and map overlay.
- **Map display** - The automatic situation map uses vanilla's `situation_data` path via `is_data_map = yes` plus the situation's own `tooltip`, `map_color`, and `legend_key` blocks. The `sol_living_standard` economy mapmode is a separate selectable mapmode using actual per-capita liquid funds (`sol_location_liquid_funds / local_sol_total_population`) for both coloring and tooltip bands: colors are linear from 0 to 0.5, with tooltip thresholds at 0.01, 0.1, and 0.5. The SOL situation panel creates a zero-size child whose `trigger_on_create` state calls `PdxGuiWidget.PushMapModeOverride('sol_living_standard')`; the widget-scoped override is removed when the situation-specific panel is destroyed, restoring the prior mapmode. EU5 reference syntax still does not expose a verified situation script field that points to a custom mapmode tag.
- **Country substitution** - `C_SOL_substitution.txt` reads `country_modifier_strength` to subtract the present SOL modifier's actual strength from `modifier:global_<good>_pop_demand`, computes `size=(1+e)(M-1)`, and accounts internal spending with the applied live strength. Requested-size and live-strength snapshots are separate. Country population is aggregated by market/pop type before basket evaluation. Explicit subscriptions choose whole groups; current and neutral contributions use the same supplied, positive-external members of those groups, with historical sizes preserving overlaps among subscribed groups. Market-keyed maps cache seven final country-adjusted unit costs with an owner scope, and each location reads seven totals.
- **Substitution lifecycle** - Humans and normal-cadence AI recompute substitution and SOL together monthly; reduced-frequency AI solves yearly. Permanent country goods modifiers update on change/missing/actual-drift state; the one-month location modifier still reapplies monthly. Guards compare observed raw totals before external arithmetic and invalidate after ownership/market/control-mode/enable/external-offset changes, missing modifiers or actual own drift. Cumulative enabled-refresh and dirty counts, the first dirty reason and affected-good readback are retained for save diagnostics. Missing market detail initializes the shared cache; January/full/load refresh rebuilds market maps and invalidates unit-cost owners. Empty/master-off states clear once; substitution-off retains external accounting and general snapshots while clearing diagnostics. Snapshot version 2 primes live-strength data on old saves. Actual month timing remains unverified; disabling substitution has been reported to restore performance.
- **Retired 1.2 chain** - Per-stratum Engel curves, religious/cultural preferences, market-hub scarcity compensation, development cancellation and `sol_era_coeff` remain retired; the restored price-only substitute response does not revive their scales.
