# 玩家月度、AI年度经济刷新

日期：2026-10-15。按用户确定的原则：玩家经济尽量月度更新，AI允许经济结果滞后。

## 修改

- stable 删除月度 sol_check_substitution_snapshot 调用及 dirty→完整求解分支。默认AI降频下，领土、市场、外部商品需求修正变化均不再触发月度整国求解；替代开关开/关都如此。
- stable 保留现有CMF手动关闭AI降频的选项，关闭后AI仍按月求解。这是显式用户覆盖，不改变默认年度策略。
- standalone 原来所有国家每月求解；现改为玩家月度、AI年度，并注册AI年度pulse。PP/M&T/JTG继承基础调度和地点应用，不需要重复覆盖。
- shared economy generator 在既有地点modifier应用遍历中补一个has_variable判断：缺少sol_location_pop_demand_modifier_size时写0，然后正常应用一个月modifier。size=0意味着SOL地点倍率1，不伪造收入/支出缓存；已有0、负值和正值均不覆盖。不额外遍历地点、不触发国家求解。
- 国家算法、替代Algorithm A、世界市场刷新频率和永久商品modifier机制没有改变。旧snapshot helper/诊断与刷新时的快照写入暂时保留，但常规月度调度不再调用guard；现有低层guard测试只验证helper，不代表在线月度调用。

## 生命周期覆盖

| 情况 | 原先是否覆盖 | 当前处理 |
| --- | --- | --- |
| 新局/载入 | 已覆盖 | after-lobby全刷新 |
| 新国家从未求解 | 已覆盖 | 月度发现国家solve status缺失，初始化一次；以后年度 |
| SOL或替代开关切换 | 已覆盖 | CMF回调清理/立即刷新，永久修正不等一年才移除 |
| 玩家接管AI | 已覆盖 | is_human直接进入下一个月度求解 |
| AI接管玩家 | 已覆盖 | 保留已有系数，等待AI周年 |
| 已有国家取得未初始化地点 | 原应用直接读变量，缺兜底 | 新增地点中性size=0；年度正式求解 |
| 取得有旧系数地点 | 无需保证最新 | 继续沿用旧系数直到年度；玩家在下月正式求解 |
| 市场/收入/商品修正改变 | 允许滞后 | 不轮询、不强制AI重算 |
| 灭亡/无人口/关闭主功能 | 已有cleanup路径 | 保留原清理 |

“最小兜底”指有值可以安全应用、显式关闭能及时清除，并非保证AI每时每刻经济一致。因此本次只新增缺地点系数的处理，未增建生命周期监控系统。
