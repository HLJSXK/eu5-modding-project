# EU5 1.4 beta compatibility audit

## 2026-10-05 official-defines cross-check

The updated official 1.4 defines confirm the recent resolution migration: `types/resolutions.txt:70-71` names `ai_will_propose` for proposals and `ai_will_do`/`ai_vote_weight` for votes; `ai_will_select` was renamed for this type. The generic-action GUI examples in `types/generic_actions.txt:82-112` also confirm `PdxGuiWidget.IsUberButtonVisible/Enabled` and `scripted_action_tooltip`. The generated location action buttons match the current vanilla examples, including the vanilla IO buttons that omit a separate `enabled` expression. The `pilgrimage_action` price key remains present in vanilla, and the capital-occupation controller guard matches vanilla. The goods/winter fixes remain consistent with the official `local_food_production_mult` addition and the current goods objects.

One missed removal was found in the copied third-party windows. `changes_data_types.md:338,592` adds `ShowRoadBuilder( Arg0 )` and removes `ShowRoadbuilder( Arg0 )`; vanilla `in_game/gui/location_window.gui:5955` uses the new spelling. Stable Glorp and M&T still used the old function in their road buttons, while standalone already used the new one. The shared `gui_14_migration.py` now requires exactly one replacement per copied window, and both generated windows have been refreshed. A scan of all other removed official script and GUI names found no further active `src/` matches.

The official script diff also lists `ai_country_should_colonize` as **added** (`changes_script_docs.md:145`). It is a valid engine trigger despite having no scripted-trigger body in the current vanilla files. This corrects the earlier inference based on the missing definition; it does **not** restore the removed `create_colonial_charter` generic-action entry point or prove that SOL's old AI restrictions run in 1.4. Official data types expose `OpenCreateColonialCharterSelection` and `ColonialCharterItem.CreateColonialCharter` as GUI functions, but neither supplies a script-side AI scoring hook for the old 500-tax-base rule.

## 2026-10-05 PR #11 cross-check

PR #11 (`c326a235`, “Add EUV 1.4 compatibility overlay for Standard of Living”) is a draft manual overlay for full SOL `260813` and CMF `2.5.*`. It recalibrates 55 goods and carries its own lifecycle, GUI, price, war, resolution, and demand-generator files. The current `beta` branch has already migrated all five deploy targets to the 1.4 reference, added `camels` as the 56th good, and replaced the old location-level pipeline with the active country solver. The PR overlay therefore cannot be merged as a package: it would regress the goods model and duplicate current runtime/UI ownership.

The cross-check identified three changes that apply to the current beta. The stable price override now targets the verified `pilgrimage_action` price object, with the generated M&T authority updated accordingly. The capital-occupation modifier now checks `exists = controller` just like vanilla. Stable and standalone resolutions now use the documented `ai_will_propose` and `ai_will_do` values to suppress AI proposals and votes; the old `ai_will_select` field is not documented for resolutions.

The PR lifecycle hooks (`on_game_started_after_lobby` / `on_game_load_after_lobby`) remain excluded because the current branch already uses GUI after-lobby callers. `on_game_started_after_lobby` is a vanilla hook; `on_game_load_after_lobby` is defined and dispatched by CMF, not by vanilla `_hardcoded.txt`. The PR's 55-good demand generator, broader old price overlay, and copied location window remain draft-only and require separate migration if a manual overlay is still needed. The 1.4 pop-type files contain only three `upper = yes` fields, but the prior 1.3 reference had the same fields while engine-observed goods `upper` demand covered five pop types. The current 1.4 evidence therefore does not justify recalibrating the parser or generated goods to a three-pop group; that behavior needs an in-game 1.4 check.

## 2026-10-04 follow-up audit

The two latest commits were audited against the 1.4 beta reference files. A concrete GUI break was found: 1.4 removes the vanilla `header_action_button_left` type from `game/in_game/gui/shared/buttons.gui` and replaces it with `header_action_button_left_uber`. The new type requires `PdxGuiWidget.IsUberButtonVisible/Enabled` and `scripted_action_tooltip`; the old `actor`, `parameter`, `left_click_and_hold_action`, `right_click_and_hold_action`, and `left_action` fields are not a compatible migration.

This is now fixed in the generators, not only in generated output. `scripts/sync_location_window.py` migrates the stable Glorp snapshot and its garrison type file; `scripts/gen_sol_mnt_compat.py` applies the same verified migration to the M&T snapshot. The four location actions (province capital, add/remove IO, and Periphora) and the garrison action now match the 1.4 reference shape. Static scans show no active legacy action fields or legacy button types in those generated files; the only remaining legacy strings are commented source fragments.

The colonial action remains an explicit boundary: 1.4 removes the `create_colonial_charter` generic action while the GUI calls the C++/GUI method `ColonialCharterItem.CreateColonialCharter`. No verified script-side replacement or AI entry point was found, so the old restriction override is retained with runtime behavior still requiring in-game confirmation.

The gold API note is precise as follows: vanilla changed `change_gold_effect` to use `scaled_gold_for_effect`; `change_gold_effect_bounded` already existed, while 1.4 adds/uses `transfer_gold_effect_bounded`. The compatibility layer does not assume the bounded interfaces inherit the old SOL wrapper.

## 保留的原版变化与兼容层差异

- **低控制度**：1.4 `inverse_control` 取消征召、兵员和水手三项惩罚，full SOL 的差量注入会自然继承。三种 modifier 仍在 `modifier_type_definitions/00_modifier_types.txt:4360,4367,6853` 定义，所以 M&T 的显式旧平衡保留。不能把对象删字段当成引擎删字段。
- **灾害恢复**：`location_base_values.local_devastation_recovery` 从 `0.005` 降至 `0.0025`，SOL 的最小注入不覆盖该项，会继承新基线。
- **粮食常量**：winter/raised levies 等数字改为 `monthly_food_productivity_*` 常量；核对 `main_menu/common/script_values/default_values.txt:525` 后，其 SOL 涉及的值仍为原来的 `-0.25/-0.50/-0.05/-0.20/-1.00`，不是额外数值回归。
- **种植/产地条件**：多个既有商品新增 `location_potential`，影响供给。基础 SOL 的需求注入会保留它们；M&T 的完整商品替换仍以 M&T 的非需求字段为准，除失效的 lumber trigger 外没有批量改写其平衡。
- **cotton / tar**：两者在旧参考文件中已存在，并非本次新增；都没有普通人口 `demand_add`，因此无需加入 SOL 人口消费矩阵。
- **人口阶层**：1.4 新增 `power_per_pop` 并调整 tribesmen 迁移，这会间接改变收入和人口分布；本模组没有覆盖 pop type 定义，继续继承 vanilla。
