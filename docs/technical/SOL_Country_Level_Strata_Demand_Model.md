# SOL 国家级阶层需求闭合（beta 开发系统）

> 本文只描述 `beta` 分支正在开发、尚未上线的国家级收入=支出系统。`main` 的稳定地点级收入=支出系统不属于本文的实现，也不使用本文的国家级求解器。

## 1. 分支和模块边界

### `main`：稳定地点级系统

`main` 的月度路径是：

```text
monthly_country_pulse
  -> gls_compute_savings_pressure
  -> every owned land location
       -> sol_compute_location_pop_demand
       -> sol_apply_country_poverty_compensation_to_location
       -> add_location_modifier
```

它只有地点 raw 系数、旧的国家贫困补偿缓存/因子应用和地点 modifier。`main` 没有 `B_SOL_country_demand_solver.txt`，也没有国家矩阵、KKT、active-set 或 minimax。

### `beta`：国家级系统（开发中）

`beta` 的月度路径按下面的模块顺序执行：

```text
monthly_country_pulse
  -> sol_solve_country_pop_demand
       A. 地点 raw 计算和国家目标聚合
       B. 地点结构分数和 confidence 计算
       C. confidence 排序后的容量分类
       D. 国家矩阵构造
       E. 常数预筛
       F. exact 诊断
       G. 近似候选（AI: proportional_fast；人类: 全策略 + minimax）
       H. gate 和策略选择
       I. 最终系数写回
  -> every owned land location
       -> add_location_modifier
```

`A_SOL_economy_effects.txt` 负责 A-D、I 和最终 modifier；`B_SOL_country_demand_solver.txt` 只负责 E-H 的固定维度线性代数、候选评估和策略选择。文件分离是加载/归属边界，Jomini effect 名称仍是全局的。

下面的“国家级成本”均指 beta 相对于共享地点 raw/modifier 基线增加的成本。地点 raw 不是国家级求解器的成本；比较完整月度路径时再把共享基线单列。

## 2. 已退休的分类方案

以下方案只保留在 git 历史或历史说明中，不属于 beta 运行时：

1. 早期四等分目标：`country_base_total / 4`，并以四类接近 25% 为分类目标。
2. 早期固定阈值门控：优先把地点交给需要最大负补偿的阶层，然后直接做 exact 解。
3. 以 `balanced_score = affinity - constant * current / (country_total / 4)` 为核心的分类。

beta 当前源码不再有 `/4` 容量 fallback。无负压时只保留每类的 1% anchor；不会把四类重新设置成四个 25% 桶。`balanced_l2` 如果出现在候选策略中，指候选的 L2 误差权重，不是旧的 25% 分类器。

## 3. beta 当前分类

对有效地点 `l` 和四个国家阶层 `e`，先得到地点份额和国家份额：

```text
p[l,e] = base[l,e] / sum_j base[l,j]
mu[e]  = country_base[e] / country_base_total
normalizer[e] = max(mu[e], 0.02)
affinity[l,e] = clamp((p[l,e] - mu[e]) / normalizer[e], -3, 3)
```

目标容量不是平均分桶。令 `Y[e]` 为 raw 加权后的国家目标、`B` 为四类 baseline 总额：

```text
pressure[e] = max(Y[e] - target[e], 0)
P = sum_e pressure[e]
floor = 0.01 * B
pool  = 0.96 * B

T[e] = floor + pool * pressure[e] / P,  if P > 1e-5
T[e] = floor,                             if P <= 1e-5
```

地点先计算结构 class 和 `confidence`，再按 confidence 从高到低处理。对候选 class `e` 的当前分数是：

```text
score[l,e] = affinity[l,e] - 0.05 * current_capacity[e] / T[e]
```

每个地点只进入一个 class；被选 class 的五类基础支出和 raw 加权支出才写入国家矩阵。四类在这里代表 `nobles / clergy / burghers / lower`，其中 `lower = commoners + tribesmen`；“四类”是求解维度，不是四等分目标。

## 3.9 精确解可行性判据（锥包含）

**先读这一节再诊断任何 `negative_factor` / `-100%` 现象。** 它把"为什么这个国家解不出来"
从经验排查变成一次可计算的判定，避免重复长链条调查。

### 判据

设 `M` 为 4x4 类矩阵，第 `k` 列 `c_k` 是第 `k` 类全部成员地点四阶层支出向量之和，
`t` 为国家目标向量。精确解要求 `M x = t` 且 `x >= 0`。该条件成立当且仅当：

```text
t ∈ cone(c_1, c_2, c_3, c_4)
```

即 `t` 落在四个列向量张成的**非负锥**内。

**线性无关不是判据。** `det(M) != 0` 只保证解唯一，不保证解非负。矩阵完全可以列无关而
`t` 在锥外，此时唯一解含负分量，运行时 `sol_country_demand_validate_class` 置 `status = -2`。
条件数同样不是判据：实测 HUN 条件数仅 55.6–96.0（良态），精确解照样不可行。

### 硬上界：分类无法突破

因为每个 `c_k` 是若干地点向量之和，而地点向量非负，所以对任意分类 `A`：

```text
cone(c_1..c_4)  ⊆  cone(所有 owned location 支出向量)
```

分类只能是全体地点锥的**粗化**，永远不能扩大可达集。因此：

> 若 `t` 不在全体地点锥内，则**不存在任何四类分类**使精确解可行；
> 增加类数、更换打分函数、调整容量分配、改善条件数全部无效。

这是封闭的数学结论，不是"尚未找到好算法"。

### 实测（HUN，2026-08-11，五个连续存档）

对全部 189 个 owned location 各给一个独立非负因子（可达集的理论极限）跑 NNLS，
相对残差仍然显著非零：

| 存档 | 全体地点锥残差 | 最小范数解的最负因子 | 需负因子的地点数 |
|---|---|---|---|
| 1337.10.02 | 0.0504 | -6.03 | 8 |
| 1337.11.02 | 0.0558 | -5.95 | 12 |
| 1337.12.01 | 0.0465 | -5.75 | 8 |
| 1338.01.13 | **0.1057** | -4.65 | **43** |
| 1338.02.02 | 0.0903 | -4.36 | 37 |

按阶层子集分解，冲突位置是确定的（残差 0.000 表示该子集可达）：

| 子集 | 残差范围 | 结论 |
|---|---|---|
| 单个阶层（N / C / B / L） | 0.000 | 各自总可达 |

但三者支出在地点层面高度耦合（nobles 与 lower 份额相关系数 0.29–0.47），
无法用非负因子分离。**

### 下次诊断的第一步

用 `tools/eu5_save_parser/cone_feasibility.py` 直接判定，不要从条件数、分类抖动或
系数量级入手：

```bash
$env:PYTHONUTF8='1'; & $env:EU5_PYTHON -m tools.eu5_save_parser.cone_feasibility <analysis_dir> --country TAG
```

- **全体地点锥残差 > 0.01** → 目标不可达，分类层无解，只能改目标定义或接受近似
- **残差 ≈ 0 但当前分类不可行** → 分类确实是瓶颈，此时优化分类才有意义

### 已排除的错误归因（2026-08-11 调查记录）

以下四条都被数据否定，不要重复：

1. **"近似解把微小负系数静默钳成 0"** — 近似解返回的 `0` 是非负约束下的**合法边界最优**，
   不是浮点噪声被钳制。严格拒绝 `delta < 0` 拦不住 `= 0`，`-100%` 照旧出现。
2. **"矩阵病态"** — 条件数 55.6→96.0，量级正常，不足以解释因子 3 倍摆动。
3. **"跨年单位支出刷新是切换触发器"** — 1337.10/11/12 单位支出完全冻结
   （nobles 恒为 3.99814），求解状态却在 10→11 之间从失败翻为成功。刷新只改变难度，
   不是切换机制。
4. **"分类器抖动是可行性的独立主因"** — 分类变化是数据变化的下游后果；1338 数据配
   1337 分类仍不可行（Class 4 = -1.089）。

### 抖动幅度（独立于可行性的问题）

`capacity_floor = 0.01` 使零压力阶层只得 1% 锚点容量。nobles/clergy 压力恒为 0
（baseline < target，需上调），因此承载它们特征的 Class 1/2 容量恒为 ~1.9–2.3，
而 Class 4 得到 140–193。Class 1 列质量仅占 Class 4 的 1.1%–3.2%，
导致 `‖W^-1 第 1 行‖ = 96–404`：压缩比 0.01 的正常月度波动被放大成 C1 的 1–4 单位跳变。

把容量改为按 `|baseline - target|` 分配可将放大倍数中位从 120.6 降到 55.9
（1338.01 的 404 降到 34.7），但**不改善可行性**（仍 2/5），且 Class 4 余量从 0.164
缩到 0.033。这是抖动与余量之间的 trade-off，不是可行性修复。

## 4. 国家级求解路径

矩阵聚合完成后得到 `M[e,c]` 和国家目标 `target[e]`。候选因子 `x[c]` 满足非负和硬总额：

```text
M x ~= target
x[c] >= 0
sum_c (sum_e M[e,c]) * x[c] = sum_e target[e]
```

执行顺序是：

1. 常数预筛：raw 四阶层已经没有可改善空间、没有非空 class、或矩阵列总额不可能时直接保留 raw。
2. exact 诊断：先诊断 4x4 class system；exact 成功直接采用，失败才进入后续近似路径。
3. AI 国家：运行一次 `proportional_fast` 目标份额分配，不枚举 active-set，也不调用 reduced 3x3 solve。
4. 人类国家：运行 `sol_country_demand_run_vertex_selector`（严格不恶化顶点枚举，见 4.1）。
   四个 L2 策略与 `minimax_ratio` 已退休。
5. AI 候选仍走宽松 gate（最差 raw 阶层不得恶化 + 平均 improvement ratio > 0）；
   人类路径的约束已内置在顶点筛选里，不再需要独立 gate。

## 4.1 人类近似解：严格不恶化顶点枚举

### 目标函数

按优先级对缩放残差 `r_s / t_s` 排序：

1. 最小化 `mean_s |r_s| / t_s`（缩放 L1）
2. 最小化 `max_s |r_s| / t_s`（缩放 L∞，仅作 tie-break）

**硬约束：两个指标都不得超过 raw（全因子 = 1）时的值。** 无候选满足则保留 raw。

tie 带宽 1%：两候选缩放 L1 相对差小于 1% 时视为并列，转比缩放 L∞。
原始空间 L1/L∞ 不参与选择。

### 为什么顶点枚举是精确最优

两个缩放范数都是分段线性，最优必在顶点取得。顶点定义为 4 个条件激活：
某行残差归零，或某因子触零界。枚举所有 `|E| + |Z| = 4` 的
（精确行集 E，置零因子集 Z）组合即可覆盖最优解。

运行时消元原语不做主元交换，因此**同时枚举 E 的所有排列**，共 209 个候选。
离线回放 2,618 个 exact 失败国家确认：排列枚举与带主元交换的参考解
**100% 一致**（最大差 0.0）；而只用固定顺序会在 3.7% 的国家上损失最多
13.9 个百分点的缩放 L1。

### 实测收益（2,618 个 exact 失败国家，11 个存档）

| 指标 | 原实现中位 | 顶点枚举中位 | 改善 | 改善案例 | 变差案例 |
|---|---|---|---|---|---|
| 缩放 L1 | 0.31544 | **0.10773** | **+17.11pp** | 91.1% | 0.0% |
| 缩放 L∞ | 0.63689 | **0.33465** | **+21.67pp** | 90.9% | 0.1% |

`raw_fallback` 占 8.9%（所有顶点都至少恶化一项）。严格约束相比无约束版本
仅损失中位 0.19pp，因为绝大多数国家的最优顶点本身就不恶化 L∞。

### 原实现的三个缺陷

1. **无策略优化优先级 1** —— 四个 L2 变体最小化平方和，`minimax` 最小化 L∞
   （即优先级 2），缩放 L1 无人负责。L2 是 L1 与 L∞ 的折中，对两者都不最优。
2. **跨策略比较量纲不一致** —— 选择按 `average_ratio`（相对 raw 的改善比）降序，
   而非按偏离水平升序；tie-break 用各策略自己的 `objective`（L2 是平方和、
   minimax 是最大比率），跨策略不可比。
3. **gate 与优先级冲突** —— "最差 raw 阶层不得恶化"是优先级 2 味道的硬约束却
   前置于优先级 1，会拒掉大幅改善平均偏离的候选。

### 代码规模

`B_SOL_country_demand_solver.txt` 从 92,745 行降到 11,802 行（**−87%**）：
209 个顶点各一次 ≤4x4 固定顺序消元，取代了 4 个 L2 变体 × 15 个 active-set
掩码 + minimax 顶点枚举。

## 5. 固定维度线性代数成本

对一个 `m x m` Gaussian/KKT 消元，理想的三角更新数为：

```text
F(m) = m(m-1)/2                         # 消元因子数
U(m) = sum_(p=1..m-1) (m-p)^2
     = (m-1)m(2m-1)/6                   # 右下矩阵更新数
```

但当前生成脚本的 `sol_country_demand_eliminate_row` 为固定维度复用，
每个消元行无条件展开 5 个矩阵列，再更新 1 个 RHS。令
`E(m) = 5F(m)` 为实际矩阵 cell 更新数，则实际消元/回代算术量为：

```text
multiply = subtract = E(m) + F(m) + F(m) = 7F(m)
divide   = F(m) + m
```

| 路径 | `m` | 乘法 | 减法 | 除法 | 触发条件 |
|---|---:|---:|---:|---:|---|
| exact 诊断 | 4（四个阶层方程，直接诊断 `M x = target`） | 42 | 42 | 10 | 每个进入国家级 driver 且有有效国家矩阵的国家 |
| 旧版 AI L2（历史基线） | 3（最多 3 个 free factor） | 21 | 21 | 6 | 仅用于下文旧存档算术对照；当前 AI 不再调用此求解器 |
| AI `proportional_fast` | 固定 4 个对角/Jacobi 修正 | 0（不做线性消元） | 0（不做线性消元） | 4 个对角除法 + 1 个硬总额归一化 | 每个 exact 失败、通过预筛且有至少 1 个 active class 的 AI 国家一次 |
| 人类 minimax | 4（free factor + worst-error 变量） | 42 | 42 | 10 | 每个 minimax 顶点 |

这组数字是脚本展开后的算术下界，不是毫秒。当前月度路径实际调用的是 `sol_country_demand_solve_classes` 的 4×4 精确诊断；源码中保留的 4×4/5×5 通用旧入口不是当前国家级月度路径的 exact 调用。候选评估还要额外做四行预测、四行 gate、目标函数和硬总额残差；它们是固定 `O(1)`，但在 minimax 顶点枚举中会被重复执行。

### 候选产生阶段：旧版 L2 从国家矩阵得到因子

上一版只统计了线性消元器本身，漏掉了消元器之前的矩阵构造和消元器之后的总额回代。这里按生成脚本实际展开的算术顺序重新计算。

对旧版 L2 候选，令 `k` 为本次 active class 的数量，`f = k - 1` 为需要求解的 free factor 数量：

```text
先构造约化系统：
  f 次列总额比值除法
  1 次目标总额比值除法
  4 * (f + 1) 次矩阵/右端乘法
  4 * (f + 1) 次右端减法
  4 * f^2 次 Gram 矩阵乘法
  3 * f^2 次 Gram 矩阵加法
  f 次右端乘法
  3 * f 次右端加法

若 f > 0，再执行固定 3x3 约化消元和回代：
  21 次乘法 + 21 次减法 + 6 次除法

最后用硬总额恢复 anchor factor：
  f 次乘法 + f 次减法 + 1 次除法
```

因此，一次 L2 候选产生过程的核心算术量是：

| active class 数量 `k` | 是否执行 3x3 求解 | 乘法 | 加/减法 | 除法 |
|---:|---|---:|---:|---:|
| 1 | 否，只计算一个 anchor factor | 4 | 4 | 2 |
| 2 | 是 | 35 | 36 | 9 |
| 3 | 是 | 53 | 53 | 10 |
| 4 | 是 | 79 | 76 | 11 |

这里的 `k = 1` 很重要：它不是一个 3x3 求解，只做四行 anchor 项计算和一次硬总额回代。

对 minimax 顶点，`k` 个 active factor 会选取 `k` 个有限边界方程。每个顶点的固定 4x4 求解仍然是 `42` 次乘法、`42` 次减法、`10` 次除法；除此之外，还要为每个被选中的阶层残差边界构造方程、计算 free factor 比值，并回代 anchor factor。当前 HUN 实际执行的 1,425 个顶点按 active class 数量展开如下：

| active class 数量 | 顶点数量 | 乘法 | 加/减法 | 除法 |
|---:|---:|---:|---:|---:|
| 2（6 个 active 集合） | 270 | 12,906 | 12,474 | 3,510 |
| 3（4 个 active 集合） | 660 | 34,800 | 33,360 | 9,240 |
| 4（1 个 active 集合） | 495 | 28,875 | 27,555 | 7,425 |
| **顶点合计** | **1,425** | **76,581** | **73,389** | **20,175** |

HUN 还额外把一次已经验证的 exact 因子重建为 minimax 候选：`3` 次乘法、`3` 次减法、`1` 次除法；它不执行 4x4 求解。生成文件中还存在 36 个单 active class 的 minimax 顶点入口，但四类都存在时被运行时门控跳过，所以不计入 HUN 的 1,425 次实际顶点。

### 旧版存档基线中的候选产生算术量

旧版 AI 的 `5,045` 次候选按 active class 数量拆分为：单类 `873` 次、两类 `2,499` 次、三类 `1,375` 次、四类 `298` 次。HUN 的四种 L2 策略合计为：两类 `24` 次、三类 `16` 次、四类 `4` 次。

| 路径 | 乘法 | 加/减法 | 除法 | 说明 |
|---|---:|---:|---:|---|
| 旧版 AI L2 候选产生 | 187,374 | 188,979 | 41,265 | 历史基线，包含约化系统构造、实际 3x3 求解和 anchor 回代 |
| HUN 四种 L2 候选产生 | 2,004 | 2,016 | 420 | 包含 44 次实际 3x3 求解 |
| HUN minimax 顶点产生 | 76,581 | 73,389 | 20,175 | 1,425 次实际 4x4 求解 |

因此，旧版基线的实际线性求解器调用次数不是 `5,045 + 1,426`：

```text
AI reduced-3：4,172 次
HUN L2 reduced-3：44 次
HUN minimax reduced-4：1,425 次
HUN exact-derived：1 次因子重建，不调用 reduced solver
```

仅线性消元和回代本身合计为 `148,386` 次乘法、`148,386` 次减法、`39,546` 次除法；约化矩阵构造、边界方程构造和 anchor 回代另外增加到上表的 `265,962 / 264,387 / 61,861`。

在进入单个候选之前，还有两段按国家或按策略执行的准备工作。它们也属于“得到候选”的成本，但不应乘到每个地点上：

| 准备阶段 | 实际调用次数 | 乘法 | 加/减法 | 除法 | 主要内容 |
|---|---:|---:|---:|---:|---|
| 国家候选准备 | 1,564 个有 runtime cache 的国家 | 20,332 | 39,426 | 0 | 目标总额、raw 总额、四个矩阵列总额、四阶层 raw 误差、gate 尺度和 active class 数量 |
| 策略矩阵准备 | 648 次 | 51,840 | 49,236 | 15,552 | 归一化矩阵、归一化目标、4x4 Gram 矩阵、右端向量和列总额尺度 |
| 候选因子产生 | 6,515 次候选尝试 | 265,962 | 264,387 | 61,861 | active-set 约化系统、minimax 边界方程、固定维度消元、回代和 anchor factor 重建 |

上表合计是 `338,134` 次乘法、`353,049` 次加/减法、`77,413` 次除法，且还没有加入候选验收。绝对值取正、数值比较、失败分支、变量复制和 effect 调度没有硬编码为固定算术次数；它们需要另用脚本操作计数或 EU5 分段计时测量。

### 精确解在流水线中的位置

精确解不在近似候选枚举之后，而是在近似路径之前执行：

```text
地点分类和国家矩阵聚合
  -> 常数预筛准备国家数据
  -> 4x4 精确诊断：直接求 M x = target
  -> 保存 exact_status
  -> exact 成功：直接采用 exact 因子
  -> exact 失败：
       AI：proportional_fast 一次性目标份额分配
       人类：四种 L2 + minimax
```

最新存档中有 runtime cache 的 `1,564` 个国家都执行了这次 4×4 精确诊断，结果分布为：

```text
exact_status = 1：21 国，精确解通过
exact_status = -1：1,266 国，主元/奇异性检查失败
exact_status = -2：276 国，精确因子出现负值
exact_status = -7：1 国，精确解残差检查失败
```

精确诊断的固定 4×4 消元和回代成本为每国 `42` 次乘法、`42` 次减法、`10` 次除法，因此 1,564 个国家的核心精确求解合计为：

```text
65,688 次乘法
65,688 次减法
15,640 次除法
```

这还不包含精确解前面的工作矩阵行归一化，以及精确解后的四个因子合法性检查、四行残差验证和诊断变量写入。精确解成功的国家现在直接采用 exact 因子，跳过全部近似候选；`selected_strategy = 7` 仅作为 exact-direct 的运行时诊断编号。

### 为什么旧版 L2 近似重，而当前 AI 更轻

两者的单次求解维度都很小，但重复方式不同：

```text
精确解：每个国家只解一次完整 4x4 阶层矩阵

当前 AI 近似：一个国家只做一次对角/Jacobi 修正，
         再做一次硬总额归一化和四行 gate，不枚举 active class 集合

旧版 AI 近似：一个国家只用一个“归一化误差平方和”策略，
         但要对每个可用 active class 集合各生成一个候选

人类近似：四个不同的“归一化误差平方和”策略，
         再加 minimax 的有限边界顶点枚举
```

因此最新存档的调用次数是：

```text
精确 4x4 诊断：1,564 次国家级求解
切换前的一阶公式静态回放：932 次候选，121 次通过旧的严格 gate（历史基线，不代表当前 exact-first + 宽松 gate 调用量）
旧版 AI active-set：5,045 次候选产生（历史基线）
HUN 四种 L2 策略：44 次候选产生
HUN minimax：1,425 次 4x4 边界顶点求解
```

### 当前 exact-first + 宽松 gate 离线回放

使用 `tmp/latest_all_country_effects_20260808` 的 `countries.csv`/`locations.csv`，并用 `--use-saved-classes` 固定存档中的地点 class。共导出 1,565 国，其中 1,505 国有有效地点数据；22 国 exact 直接采用。其余国家按角色分别回放 Fast 或玩家五策略：

| 路径 | 估计通过 | raw fallback | 最终采用（含 exact） | 总 L1 减少 | 估计国家平均/中位 improvement ratio | 已通过国家恶化比例 P90 / 有限最大值 |
|---|---:|---:|---:|---:|---:|---:|
| AI `proportional_fast` | 844 | 639 | 866 | 279.08 | 0.114 / 0.022 | 22.8% / 150.1% |
| 玩家 L2 + minimax | 1,267 | 216 | 1,289 | 633.69 | 0.222 / 0.137 | 16.9% / 185.9% |

尾部统计中各路径各有 1 个国家的 raw 阶层误差低于 `epsilon`，因此该阶层的相对恶化定义为 `inf`；上表 P90/最大值只列有限值。作为性能对照，关闭 exact-first 后同一 Python 回放约为 AI 1.66 s、玩家 22.54 s；启用 exact-first 约为 AI 1.70 s、玩家 21.15 s。这个测量包含 CSV 读写和 Python 进程开销，不是 EU5 月脉冲 wall-clock；它说明 Fast 的估计阶段开销很小，而玩家路径跳过 exact 成功国家的候选搜索可节省约 6%，AI 端 exact 诊断的固定成本会略高于节省的一次 Fast。

按交接稿的固定 644 国分母（存档旧预筛集合）回放时，exact 直接采用 22 国；Fast 估计通过 248 国、raw fallback 374 国，最终采用 270 国，总 L1 减少 `265.21`；玩家估计通过 586 国、raw fallback 36 国，最终采用 608 国，总 L1 减少 `606.67`。交接稿旧严格 gate 的对应结果为 Fast `121/644`、L1 `56.31`，L2 `309/644`、L1 `531.58`；因此宽松 gate 在这组固定分母上显著扩大覆盖和总收益，但 Fast 的估计国家平均/中位 improvement ratio 只有 `0.262/0.243`，玩家为 `0.358/0.339`，不能把覆盖率提升理解成单国质量同步提升。

精确解的核心消元合计只有：

```text
65,688 次乘法
65,688 次减法
15,640 次除法
```

而旧版近似候选的因子产生阶段合计为：

```text
265,962 次乘法
264,387 次加/减法
61,861 次除法
```

这还没有计入近似候选前的策略矩阵准备，以及每个候选之后的四阶层预测、非负检查、总额残差检查、四阶层改善 gate、目标函数和排名缓存。完整候选验收还会增加约 `124,596` 次乘法、`170,201` 次加法、`58,635` 次减法和 `65,150` 次除法的固定成功路径上限。

旧版近似路径的额外成本来自三个具体重复：

1. 每个 active class 集合都要重新构造约化矩阵和约化右端。即使国家矩阵 `M` 已经聚合完成，也不是把同一个解重复读取。
2. minimax 要枚举边界组合。四类都存在时，运行时实际执行 `270 + 660 + 495 = 1,425` 个边界顶点；这远大于一次精确解。
3. 每个候选都必须单独预测四个阶层、检查硬总额、计算四个误差并执行 gate。候选失败也可能已经完成部分求解和验收。

所以“精确解的固定维度算术量较小”和“L2 近似路径很重”并不矛盾：前者是一次国家级直接求解，后者是一个受约束的候选搜索过程。精确解失败后才进入近似，成功时的 exact 成本会替代该国近似候选成本。

### 同一个国家的一次精确解与一次 L2 策略

下面假设地点分类、国家矩阵 `M`、四阶层目标和 raw 误差已经准备完成，只比较国家求解模块本身。

一次直接精确解执行：

```text
4 行工作矩阵归一化：20 次除法
4x4 Gaussian 消元和回代：42 次乘法 + 42 次减法 + 10 次除法
```

因此一次精确解的核心量约为：

```text
42 次乘法
42 次减法
30 次除法
```

如果精确解通过，还会做四个因子合法性检查和四行残差验证，但不会枚举 active class 集合，也不会计算策略目标函数或排名缓存。

一次 L2 候选不是完整的 L2 策略。给定一个 active class 集合后，单个候选的产生和验收量如下：

| active class 数 | 单个候选产生 | 单个候选验收 | 单个候选合计 |
|---:|---|---|---|
| 1 | `4` 乘法 + `4` 加/减法 + `2` 除法 | `20` 乘法 + `36` 加/减法 + `10` 除法 | `24` 乘法 + `40` 加/减法 + `12` 除法 |
| 2 | `35` 乘法 + `36` 加/减法 + `9` 除法 | 同上 | `55` 乘法 + `72` 加/减法 + `19` 除法 |
| 3 | `53` 乘法 + `53` 加/减法 + `10` 除法 | 同上 | `73` 乘法 + `89` 加/减法 + `20` 除法 |
| 4 | `79` 乘法 + `76` 加/减法 + `11` 除法 | 同上 | `99` 乘法 + `112` 加/减法 + `21` 除法 |

单个候选的成本并不总是比精确解大；例如双阶层候选的产生阶段比一次完整精确消元还小。L2 的真正成本来自同一国家要执行多个候选，而不是来自某一个 3x3 求解。

一次完整的旧版 AI L2 策略还要先做一次策略矩阵准备（`80` 次乘法、`72` 次加法、`24` 次除法），再枚举所有 active class 集合。因此一个国家的完整旧版 AI L2 策略大致为：

| active class 数 | 候选数量 | 完整 L2 策略乘法 | 完整 L2 策略加/减法 | 完整 L2 策略除法 |
|---:|---:|---:|---:|---:|
| 2 | 3 | 183 | 224 | 67 |
| 3 | 7 | 390 | 497 | 137 |
| 4 | 11 | 801 | 972 | 239 |

其中 `k = 4` 的 `11` 个候选是 `6` 个双阶层集合、`4` 个三阶层集合和 `1` 个四阶层集合；四个单阶层集合被运行时门控跳过。对人类国家，四种 L2 策略会把这张表中的策略准备、候选产生和候选验收分别重复四次，之后还要再执行 minimax 顶点路径。

这里的“候选评估”不是地点循环，也不是把所有算法重新跑一遍；它是对某一个“近似策略 + active class 集合”产生的具体四阶层因子向量进行验收和排名。人类国家的 minimax 候选还附带一个具体的有限边界顶点。候选尝试先执行对应的固定维度线性求解（exact-derived 候选除外），求解失败会提前退出；求解成功后才进入下面的完整验收：

1. 检查线性求解状态；奇异主元、数值失败或无解立即拒绝。
2. 检查四个 class factor；小于 `-0.00001` 的真正负值拒绝，`[-0.00001, 0)` 截到 0。
3. 用 `prediction[e] = sum_c M[e,c] * factor[c]` 预测四个阶层的总支出。
4. 检查硬总额残差 `abs(sum(prediction) - sum(target))` 是否超过总额容差。
5. 对每个阶层计算 `abs(prediction[e] - target[e])`，并和 raw 误差比较改善量、改善比率和归一化误差。
6. 执行宽松 gate：raw 绝对误差最大的阶层改善量不得低于 `-max(0.00001, raw_abs_error * 1e-9)`；四阶层 improvement ratio 的平均值必须大于 `0`。
7. 计算策略目标：四种 L2 策略将四个归一化误差平方求和；minimax 取四个归一化误差的最大值，并检查 worst-error 变量覆盖所有阶层。
8. 通过数值检查的候选更新该策略的最佳候选；通过四阶层 gate 的候选才参与最终策略选择。

因此 `6,515` 次候选尝试绝不是 `6,515` 次简单矩阵除法。每次尝试至少包含一次候选路线的状态检查；能够得到数值解的尝试还会继续执行“因子非负检查 + 四行矩阵预测 + 硬总额检查 + 四阶层误差计算 + 四阶层 gate + 目标函数 + 排名缓存”。

因此旧版存档基线中，候选产生阶段已经包含 `265,962` 次乘法、`264,387` 次加/减法、`61,861` 次除法；其中实际线性消元和回代只占 `148,386` 次乘法、`148,386` 次减法、`39,546` 次除法，其余是约化矩阵构造、边界方程构造和 anchor factor 重建。以上仍然没有包含候选验收固定项；精确诊断的 `65,688 / 65,688 / 15,640` 核心算术应单独加在国家级流程的近似候选之前。

候选验收 effect（源码名称为 `sol_country_demand_approx_assess`，名称仅用于定位）的完整静态 body 包含 99 个 `set_variable`、37 个 `change_variable` 和 53 个条件分支。把这个完整 body 的静态展开量乘以实际 `6,515` 次候选尝试，得到 644,985 次变量设置、241,055 次变量增量修改和 345,295 次条件判断；这不是 CPU 指令计数，也不是每次调用的实际执行量，失败候选会因条件分支提前跳过后续 body。这个静态量还没有把候选调用的四行矩阵预测、硬总额残差、四阶层 gate、目标函数和线性求解辅助 effect 展开进去。minimax 的生成入口共有 1,461 个，当前 HUN 实际执行了 1,426 个；这也是为什么只看 3x3/4x4 求解的乘除法，不能判断国家级求解流程的热度。

如果候选已经得到数值解并完整走到验收，验收阶段本身还会执行：四行矩阵预测的 16 次乘法和 12 次加法、总额求和的 3 次加法、总额残差的 1 次减法、四阶层误差和改善量的 8 次减法、四阶层平均量的 8 次加法、四个改善比例和四个归一化误差比例的 8 次除法，以及两个平均值的 2 次除法。L2 候选还要为四个归一化误差各做一次平方乘法和累加目标；所以一次完整 L2 验收约为 `20` 次乘法、`27` 次加法、`9` 次减法、`10` 次除法。一次完整 minimax 验收不需要平方和，只取最大值，约为 `16` 次乘法、`23` 次加法、`9` 次减法、`10` 次除法。

按 `5,089` 次 L2 尝试和 `1,426` 次 minimax 尝试计算，完整验收路径的固定算术上限约为 `124,596` 次乘法、`170,201` 次加法、`58,635` 次减法、`65,150` 次除法；绝对值取正和条件比较仍未计入。这个上限不能替代实际执行计数，因为奇异或无解候选会提前退出。

分类排序的输入是 `10,366` 个有效地点，排序比较次数的数量级约为 `n log2(n) = 138,278`；但排序实现的单次比较成本由 EU5 引擎决定，不能和脚本 `set/change/if` 直接相加。当前可证据化的结论是：排序不是唯一可疑热点，候选评估和 minimax 顶点展开同样必须单独采样。

## 7. 与 main 地点级路径的正确比较

下面直接写出两条路径的模块组成，不用一个字母代表一整段未知工作量。设一个国家有 `n` 个有效地点：

```text
main 的国家月度路径 =
  共享的地点 raw 计算（每个地点一次）
  + main 独有的旧国家贫困补偿因子计算与写入（每个地点一次）
  + 共享的地点 modifier 应用（每个地点一次）
  + 国家贫困压力的少量国家级更新

beta 的国家月度路径 =
  共享的地点 raw 计算（每个地点一次）
  + beta 的阶层份额、容量分数和 confidence 计算（每个有效地点一次）
  + 按 confidence 排序并按顺序分配地点到四个阶层（每个有效地点参与一次排序/分配）
  + 将已分类地点的四类基础支出和 raw 加权支出累加到国家矩阵（每个已分类地点最多累加四个阶层列）
  + 常数预筛：检查是否存在可改善空间、有效阶层数、矩阵列总额和秩
  + 对通过预筛的国家执行 exact 诊断（固定维度线性消元）
  + 对需要近似的 AI 国家执行 proportional_fast 目标份额分配和候选验收
  + 对人类国家执行四种 L2 策略、minimax 有限边界顶点求解和候选验收
  + 在选定因子后再次扫描国家地点，记录四阶层预测误差和 raw 对比诊断（每个有缓存的国家内部扫描其地点）
  + 共享的地点 modifier 应用（每个地点一次）

因此，比较国家级新增成本时，应逐项比较：

```text
beta 新增成本 =
  地点阶层分类与国家矩阵累加
  + 常数预筛
  + 实际进入国家的 exact 诊断
  + AI `proportional_fast` 固定修正、硬总额归一化及一次候选验收
  + 人类国家的多策略线性求解及 minimax 顶点的完整验收
  + 选定因子后的地点级误差诊断扫描

main 对应的独有成本 =
  旧国家贫困补偿因子的地点级计算与应用
```

共享的地点 raw 和地点 modifier 必须从比较中抵消；没有 EU5 profiler 或同一月度脉冲的分段计时，不能把上述任一模块换算成 CPU 百分比或毫秒，也不能仅凭排序的比较次数断言哪个模块是热点。

### 7.1 main 既有地点级系统的实际计算量

以下只计算 `main` 的稳定地点级收入=支出路径，使用最新存档的 `13,588` 个 owner land location 和 `1,565` 个国家作为一次月度脉冲的规模。地点分类、国家矩阵、精确解、近似候选和国家级最终诊断都不在这条路径里。

正常月度脉冲在贫困补偿缓存已经初始化后，执行：

```text
国家级储蓄压力准备：每个国家一次
  -> 地点 raw 收入/支出计算：每个地点一次
  -> 旧贫困补偿因子乘法：每个地点一次
  -> 地点 modifier 写入：每个地点一次
```

`main` 的一次地点 raw 计算固定包含 `13` 次乘法、`21` 次加法、`5` 次减法、`2` 次除法；旧贫困补偿应用再增加 `1` 次乘法和 `1` 次减法。因此每个地点的正常月度算术量为：

```text
14 次乘法
21 次加法
6 次减法
2 次除法
```

乘以 `13,588` 个地点后，地点部分为：

```text
190,232 次乘法
285,348 次加法
81,528 次减法
27,176 次除法
```

国家级储蓄压力准备的静态 body 每个国家包含 `6` 次乘法、`7` 次加法、`1` 次减法、`1` 次除法。乘以 `1,565` 个国家后增加：

```text
9,390 次乘法
10,955 次加法
1,565 次减法
1,565 次除法
```

所以，正常月度脉冲中，`main` 稳定路径合计约为：

```text
199,622 次乘法
296,303 次加法
83,093 次减法
28,741 次除法
```

按脚本变量操作展开，正常月度地点部分约为每地点 `50` 个 `set_variable`、`10` 个 `change_variable`、`11` 个条件分支；乘以 `13,588` 个地点后为 `679,400` 个变量设置、`135,880` 个变量修改、`149,468` 个条件分支。国家储蓄压力准备再增加 `39,125` 个变量设置和 `17,215` 个条件分支。

首次初始化月和年度贫困缓存刷新月会多执行一条地点级缓存刷新路径。该额外路径对每个地点执行一次 raw 计算和 `11` 次国家累计加法，即：

```text
13 次乘法
32 次加法
5 次减法
2 次除法
```

因此在“缓存刷新 + 正常月度应用”同时发生的月份，地点级部分变为每地点：

```text
27 次乘法
53 次加法
11 次减法
4 次除法
```

也就是仅地点循环就达到：

```text
366,876 次乘法
720,164 次加法
149,468 次减法
54,352 次除法
```

这还没有加上该刷新路径的国家级贫困补偿汇总和最终因子计算。年度刷新单独发生时只有额外缓存刷新遍历；正常月份则只有一条 raw + 应用遍历。

### 7.1 代码展开的模块基线（只用于相对比较）

下面是生成文件中的静态 effect body 计数。它们不是 CPU 时间；同一个 body 可能按地点、按 class 或按候选重复调用，所以必须和上面的调用次数一起看。

| 模块 | 版本 | body 行数 | `set_variable` | `change_variable` | 分支 | 实际重复单位 |
|---|---|---:|---:|---:|---:|---|
| raw 计算（共享基线） | `main` | 136 | 47 | 10 | 10 | 每个有效地点 1 次 |
| raw + beta 分类缓存 | `beta` | 165 | 68 | 12 | 12 | 每个有效地点 1 次；多出的部分是份额/分数缓存 |
| 旧 poverty 因子应用 | `main` | 12 | 3 | 0 | 1 | 每个有效地点 1 次 |
| capacity 分数准备 | `beta` | 29 | 14 | 0 | 1 | 每个有效地点 1 次 |
| confidence 顺序分类 | `beta` | 19 | 6 | 0 | 1 | 每个有效地点 1 次 |
| class 矩阵累计 | `beta` | 57 | 15 | 22 | 6 | 每个已分类地点最多 4 次 class 调用 |
| 国家 driver 初始化/编排 | `beta` | 518 | 373 | 23 | 20 | 每个进入国家 driver 的国家 1 次 |
| 最终误差诊断 | `beta` | 72 | 38 | 5 | 4 | 每个有 cache 的国家 1 次，内部再扫地点 |
| final class 应用 | `beta` | 7 | 2 | 0 | 1 | 选中候选时，每个地点最多 4 次 class 检查 |

这个表说明了两个容易混淆的事实：beta 的 raw 计算保留了共享地点基线，但在同一个地点缓存阶段附加了分类数据；而 `B` 中 1,461 个 minimax 顶点入口只在满足人类国家路径和 active-set 预筛的国家中被调用，不能把 1,461 乘到所有国家或所有地点上。

在没有 EU5 profiler/frame-time 采样前，不能把这些静态操作换算成 CPU 百分比或毫秒。但从调用次数已经能确定：beta 对 `10,366` 个有效地点至少增加分类/聚合和最终诊断扫描；main 只有每地点一次旧 poverty apply。故“beta 国家级算法已经比 main 地点级算法更轻、所以 main 才是热点”目前没有证据，反而更合理的待测假设是：共享 raw 可能是共同热点，beta 的国家级增量由地点分类/聚合扫描和人类 minimax 候选组成，main 的增量是旧 poverty apply。必须用同一月度脉冲的游戏 profiler 或显式分段计时日志验证三者占比。

## 8. 可追踪的运行日志字段

性能追踪应按模块记录，而不是只记录 effect 名称：

```text
raw_locations, classified_locations, ordered_class_locations,
matrix_columns, prefilter_rejects, exact_attempts,
approx_attempts_by_strategy, minimax_vertices,
gate_passes, raw_fallbacks, final_apply_locations
```

这些计数应分别写在国家级 driver 的阶段边界；它们描述执行路径，不代表 wall-clock。当前存档已经提供国家/地点/候选计数，可作为第一份基线；下一步若要确定“地点 raw 是否最热”，需要在 EU5 profiler 中对 `main` 和 `beta` 各采集一次完整月度 pulse，并保持相同存档和速度设置。
