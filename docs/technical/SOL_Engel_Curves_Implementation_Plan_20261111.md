# SOL 恩格尔曲线恢复：实现计划与审计契约

日期：2026-11-11。状态：**待审计的设计计划，尚未实现**。

代码基线：`beta`，`bc4b75b894f5bd05f4f3ef282d15e13c75f992ae`。目标为当前五种构建，不把历史 `main` 或旧报告中的状态当作当前源码事实。本次只新增本文，不改变运行脚本、配置、生成产物或发布版本。

## 1. 目标与已确定的边界

恢复随购买力变化的消费结构，沿用国家逐商品 modifier 与现有国家阶层求解器。

已经确定的设计：

1. 使用**必需、日用、奢侈三类曲线**；每个替代组恰好属于一类，同类组共用曲线。
2. 共用 **16 个购买力档位**，档内固定值，**不插值**。
3. 所有阶层共用相同三条曲线；阶层差异由既有基础篮子与各阶层购买力表达。
4. 购买力数据计算到“地点 × 收入阶层”；继续区分七种有收入人口类型的基础篮子。
5. 曲线配置在生成期变成常量脚本；运行时不建立一张 16×3 的倍率 variable map。
6. 运行时通过 map 汇总“本国 × 市场 × 人口类型 × 消费类别”的调整人口。
7. 恩格尔曲线与价格替代合成同一套国家商品倍率，随后重新计算基础支出并运行现有求解器。
8. 不新增逐地点预算归一化、不新增求解维度、不新增收敛迭代、不承诺精确匹配理想商品总量。

此处“曲线”是**相对需求倍率曲线**，不是三个必须相加等于 1 的预算占比，也不是引擎最终商品需求量的直接曲线。最终消费总量仍由已有流动资金、地点倍率和国家求解器控制。

首版工程提案：与现有替代组共用开关和刷新周期，不新增独立 GUI 控件、自动修正集合或逐 POP 遍历。若审计要求独立开关，应作为明确的范围变更补充生命周期与测试，而非实现时暗中增加。

## 4. 购买力口径与计算重排

收入阶层集合 `s` 为 nobles、clergy、burghers、commoners、tribesmen。

沿用现有计算：

`F[l,s] = max(income[l,s] - maintenance[l,s], 0) × max(1 + country_savings_adjustment, 0)`。

曲线输入：`y[l,s] = F[l,s] / P[l,s]`，只在 `P>0` 时求值。其中平民人口为 laborers + peasants + soldiers；三类共用同一个平民人均资金与三个倍率，但保留各自基础商品数量。不得对三个类型各分配完整的平民资金池。

原生人口以千人为单位，因此不再额外乘1000，也不使用已乘1000的人口显示值。输入保持月度，不乘生活水平显示的年化系数。地点生活水平加值、百分比福利修正不进入该输入。它是资金购买力代理，不是经物价指数修正的实际收入。

将地点函数拆成两个有明确依赖的内部步骤（名称为拟定名称）：

- `sol_prepare_location_purchasing_power`：计算收入、维护后净收入、流动资金；写回已有变量。
- `sol_compute_location_demand_from_prepared_funds`：用最终国家商品倍率计算单位支出、原始地点倍率和生活水平等原有派生数据；不重算收入。

建议新顺序：

1. 保留现有地产维护缓存的初始化/刷新职责，确保本轮所需缓存已就绪；不得因提前购买力而重复进行建筑扫描。
2. 每国计算一次存款压力。
3. 替代开启时，在现有地点人口聚合遍历中计算购买力、查档、累计普通人口与三类调整人口。所有原来会进入地点需求计算的陆地点都要准备购买力；没有市场的地点只跳过市场累计，不能被漏掉。
4. 按市场合成价格替代与恩格尔影响，写国家有效商品倍率并使单位支出缓存失效。
5. 后续已有地点遍历读取准备好的资金，计算支出、raw倍率、国家矩阵和生活水平。
6. 执行原有raw-only、精确或近似求解分支，然后沿用修正写回与显示收尾。

替代关闭时不建立恩格尔map，不新增一趟空预处理遍历；直接在原地点需求路径准备资金一次，再计算支出。保留原地点入口作为兼容包装时，应使用显式调用路径区分“准备并计算”和“已准备后计算”，不能只凭变量存在就判断本轮已准备。

购买力缓存每次完整刷新重算一次。读取到存档中已有变量不代表它属于本轮。小于5地点的国家或求解器两个开关都关闭的国家，也仍需在替代开启时获得恩格尔结构，随后进入既有raw-only分支。

## 5. 数学实现：三类调整人口

符号：`l`地点，`m`市场，`p`人口类型，`h`替代组，`g`商品，`c(h)`组类别；`s(p)`为人口类型到收入池的映射。

定义：

- `n[l,p]`：地点人口，原生千人单位。
- `f[c,y]`：16档表返回的类别倍率。
- `P[m,p] = Σ_l n[l,p]`：现有普通人口聚合，求和仅含本国且属于市场m的地点。
- **`A[m,p,c] = Σ_l n[l,p] × f[c,y[l,s(p)]]`**：新增三类调整人口。
- `q[p,g]`：目标构建实际校准后的基础商品数量。
- `v[g]`：现有国家聚合使用的默认商品价格。保留其权重口径，不在此改为当地价格或资金权重。

### 5.1 保留原算法A的组内价格权重

在当前国家与市场资格筛选后，组h有效商品集合为 `E[m,h]`，现有离散价格权重为 `w[m,g]`，历史组尺寸为 `H[h]`。

对人口p订阅的组、且属于该组的有效商品g，定义：

`K[m,p,h,g] = H[h] × w[m,g] / Σ_(j∈E[m,h]) w[m,j]`。

保留原来的中性分母：

`Z[m,p,g] = Σ_(订阅且含g的有效组h) H[h] / |E[m,h]|`。

只对 `Z>0` 的原有效项目累加：

`Base[g] += v[g] × q[p,g] × P[m,p]`。

`Target[g] += v[g] × q[p,g] × (Σ_h K[m,p,h,g] × A[m,p,c(h)]) / Z[m,p,g]`。

最后 `M[g] = Target[g] / Base[g]`；Base为零时沿用当前中性回退与清理规则，不通过很小的假分母创造需求。

### 5.2 等价性与跨组商品

逐地点理想响应为：

`D[l,p,g] = (Σ_h K[m,p,h,g] × f[c(h),y[l,s(p)]]) / Z[m,p,g]`。

将 `Σ_l n[l,p] × D[l,p,g]` 展开，正好得到上一节用A聚合的公式。成立条件是同一国家、市场、人口类型的基础篮子、资格、价格权重和Z共享，且本方案没有逐地点再归一化。本轮满足这些条件；未来加入地点文化、宗教、气候偏好时必须重新检查，不能无条件继续复用。

商品可属于多组甚至跨消费类别；每条组成员贡献分别乘对应A，然后合并。不能给商品选一个“主类别”来计算，不能丢掉重叠组，也不能再把跨组倍率额外乘一次。

**曲线倍率加在组归一化后的贡献上。** 不把同一类别倍率乘进某组所有商品的价格权重后再归一化，否则共同倍率会在组内分子分母中抵消，恩格尔功能失效。

Z继续使用不含恩格尔倍率的原中性篮子。把同样的倍率加进Z会改变本方案，并可能抵消预期效果。

### 5.3 国家modifier与求解器

保留现有外部修正合成：`E[g] = max(0, 1 + live_global_offset[g] - old_own_scale[g])`。

新自有修正为 `size[g] = E[g] × (M[g]-1)`；地点记账使用 `effective[g] = E[g] + size[g]`，仅乘一次。

自有旧scale应在覆盖缓存前扣除；自动修正仍读预计算结果，不能递归读取自身总modifier。外部E为零的商品仍不可因恩格尔倍率变正而重新开启。

国家求解仍是 `A_matrix × location_factors = available_funds`，商品权重改变矩阵，不改变资金目标。本文中的调整人口A与求解矩阵是不同对象，实现命名必须区分。

这是国家商品接口下的聚合近似。沿用现有权重，不引入最终地点倍率反馈至商品聚合，不宣称每地每阶层预算或最终全国商品总量均精确命中。

## 6. 查表代码与map生命周期

### 6.1 常量查表

生成15个阈值构成的平衡二分条件树；每个有效收入池最多4次阈值比较，每个叶子写三个局部倍率常量。

同一地点平民三个类型共享一次查档结果。没有订阅组的收入池不必为恩格尔查档，但收入本身仍按原系统计算。树外的人口/有效性判断不计入“最多4次”。

不要建立逐商品、逐组或逐档自动modifier；不要在GUI/tooltip/auto modifier评估中查表或累计。运行态只在完整经济刷新中计算。

### 6.2 聚合map

建议沿用现有临时全局map模式，新增固定名称族 `sol_engel_market_population_<pop>_<class>`，key为market scope，value为A。实际名称需由生成器一次定义并被所有目标复用。

这些map只保存**当前正在刷新国家**的临时统计，不是持久可供任意国家读取的市场经济缓存。沿用同步顺序执行；禁止在生命周期中加入延期事件、并发假设或可重入的跨国经济调用。

1. 国家处理开始时，对其涉及的市场与有效人口—类别组合初始化为0。
2. 每地点累计时：读取旧值；在一个局部数值表达式中计算 `old + n × f`；先删除旧key，再添加新值。现有API不能假定add覆盖已有key。
3. 进入市场展开后，将各组合读取为局部值，组成员循环复用；不能每处理一个商品成员重新查map。
4. 使用完后删除本轮key并清理局部量。无人口组合可生成期/运行期跳过，但不能读上一个国家残留值。
5. 两国共享市场的顺序交叉测试必须通过。保存/读档后残留临时map不可信：重新初始化再读取；不增加对旧临时值的依赖。

保留普通人口P的map，因为Base与原订阅检查仍需要它。不能用A替代P作为分母，否则改变倍率定义；也不能只维护一份“该市场全部阶层调整人口”。

## 7. 性能预算：分开统计三块

所有数值区分数学业务操作、变量effect语句、map读写、条件、遍历、原生计时；禁止混用。

设 `L`为处理地点数，`M`为本国市场数，`I`为参与曲线的收入池数，`J`为有效人口类型—消费类别组合数。J由实际订阅与归类生成，不能硬编码18。基础目标当前无部落订阅，因此 `J≤18`、`I≤4`；通用上界为21和5。

### 7.1 基础运算

现有收入、资金、维护等只前移，不重复计算；新增每有效收入池一次人均除法。额外遍历优先融合进替代现有地点聚合。保持国家涉及市场的单位支出缓存，不将246个商品—人口组合搬到每地点重算。

### 7.2 国家求解器

不改变四维矩阵、分类、209候选或求解轮数。只因输入变化，精确成功率、近似门控率及候选有效率可能变化，必须纳入实测；不能声称耗时严格不变。

### 7.3 替代与恩格尔

新增主要成本为 `O(I L + J L + J M + 原有市场组成员展开)`，不是逐地点遍历所有商品，也不是 `16×20×L`。

按上述明确map实现，可单独审计新增聚合成本：

| 工作 | 上界/计划计数 |
|---|---|
| 人均除法 | `I L` |
| 阈值比较 | `4 I L`，不含有效性guard |
| 叶子常量写入 | `3 I L` |
| A累计的map数值读取 | `J L` |
| A累计的局部set表达式 | `J L`，每项内含乘法与加法 |
| A累计的map删除、添加 | `2 J L` |
| map初始化与使用后清理 | 至多 `3 J M` 次map写操作 |
| 市场阶段A读取为局部值 | `J M`次读取，另计赋值与清理 |

这些是新增子步骤的可核对计数，**不是完整新增成本**：还需统计每收入池局部变量、人均计算语句、guard、scope切换、组内多一次乘法与已有汇总结构的改动。若重用一个累计临时值，不能给每项虚构一次必须清理的成本；但仍遵守局部变量清理契约。

以100地点、2市场、I=4、J=18为上界示例：查档最多1600次阈值比较；A累计1800次map读取、1800次局部set、3600次map写；初始化/清理108次map写，市场展开36次map读取。实际缺人口或缺类别时下降。

先前讨论中的“每地200次”“277次”“整体增加10%–30%”等不是此三类方案的测量值，不作为验收承诺。84降到最多18只说明逐地点汇总槽位减少约79%，不能解释为整个SOL或全部替代组耗时下降79%。

### 7.4 原生profile基线与新实验

历史窗口约20个月，完整刷新31.837原始单位，其中替代刷新14.578、地点基础需求5.799、精确解0.186、近似入口9.312；入口有包含关系，不重复相加。简单乘减与含map的单位支出每百万变量语句成本相差约3倍，不能统一用“每操作时间”换算。

新实验至少三组：原代码、重构后全1表、重构后三类16档实际表。相同存档、MOD顺序、游戏速度与采集区间；每个干净profile样本启动新的游戏进程，Start/Stop/Restart不会清空旧计数。初始化迁移成本与稳定运行分别采样，至少重复3轮报告中位值与范围。

分别记录基础计算、替代刷新中的购买力/查表/map/市场展开、精确解、近似门控与扫描、自动modifier评估次数。记录L/M、原有篮子组合数、I/J、各档占比与求解分支，避免把国家规模变化当作算法变化。另做墙钟推进速度对照，因为原生需求/市场重算不在脚本profile里。

性能通过条件首先是结构性约束：没有新增全图POP遍历、没有逐地点商品展开、没有按月重算全部AI、没有重复收入计算、没有新增一套56商品auto modifier。具体可接受耗时增幅由原生A/B结果交审计评定，不用未验证百分比代替。

## 8. 兼容、开关与存档

五目标共用数学实现与曲线配置：stable、standalone、PP、M&T、JTG。生成器传入最终数量、组成员、订阅、历史N及目标特有排除；不能只给stable新增逻辑。

- PP：保留零lumber与victuals既有处理，silk按当前组成员继承类别，具体数量以PP生成结果为准。
- M&T：沿用换价后篮子与目标维护缓存；购买力提前不得绕过M&T维护分摊覆盖。
- JTG：按当前86种商品profile展开；20组类别共用，额外商品也有组贡献。不得沿用旧“额外商品中性”捷径。
- 奴隶：继续零商品需求，不建立收入或恩格尔贡献；原生food子系统不变。
- 部落民：保留收入预算和现有无订阅状态；不为了凑齐三类而新增消费。
- 原生文化、宗教、疾病、资格、价格弹性等尚存影响不在本任务中统一接管；保留当前行为并在实际需求核验中识别其干扰。

关闭替代时：回到现有外部商品倍率与收入需求路径，清理自有商品scale及恩格尔临时状态；不改变外部mod的商品修正。再次开启按现有同步刷新职责重建。

增加一个持久**国家计算语义版本标记**，在完整成功刷新后更新。正常读档复用同版本缓存；旧标记缺失或版本不符时，在原生国家同步月度入口安排一次完整修复，之后恢复人类月度/AI原有年度或设置调度。这个标记不是“每次读档检测器”。

首次迁移可能让各国在同一月付一次计算成本，应单独记录；在新结果准备前不删除旧有效需求，使其保持到安全刷新。新局沿用原生 after-lobby 初始化。禁止GUI执行脚本、GUI-backed CMF读档桥或未经证实的on_game_load。

所有权变化、无市场、市场消失、国家形成与灭亡沿用当前调度约束：AI不因每次地图变化额外全算，新领地使用现有安全缓存兜底直到下一次完整刷新。新临时map不承担跨月缓存，必须处理无状态国家清理。

显示仍读取最终有效商品倍率；文案应说明现在包含价格替代与恩格尔结构，而不是将组合倍率继续标为纯价格响应。不新增GUI执行或每帧经济计算。若显示文案调整需要生成器变更，按既有本地化链及BOM规则执行。

## 10. 实施顺序与阶段交付

### 阶段A：锁定规格与可复核基线

冻结当前生成输出、配置与存档fixture；解析五目标实际篮子与I/J；完成独立逐地点oracle。交付分类草案、单位证据、16档参数候选与纯价格中性基线。参数尚未通过审计时只允许全1功能回归。

### 阶段B：只重构购买力计算

拆函数、重排收入准备，先不改变商品响应。检验全1/关闭状态下各地点收入、流动资金、基础支出、raw倍率、国家矩阵、最终倍率和显示值与基线一致。M&T维护数据及无市场地点必须覆盖。通过后再进入曲线阶段，避免把重构偏差误归为曲线效果。

### 阶段C：三类16档与A聚合

生成常量二分树、有效组合map、市场级组响应；启用明确非中性测试表验证oracle。完成跨组商品、外部modifier扣除、重复刷新与国家共享市场测试，记录计数器。

### 阶段D：五目标、生命周期与显示语义

生成全部目标；实现一次性版本修复与关闭清理，覆盖新旧存档及多人同步。必要文案说明组合倍率。完整生成链check与既有回归通过。

### 阶段E：参数校准和实机A/B

审定真实16档表，运行存档重放、需求/阶层支出核验与profile三组对照。阶段交付性能分解、档位分布、经济响应、误差和日志；未经实测不宣称恢复逐POP精度或给出速度提升承诺。

### 阶段F：审计关闭与发布准备

将实际实现与本文逐项对照，解释所有偏离；更新项目现状文档与BRIEF、相关知识规则和来源（按知识捕获触发条件），运行所需知识测试。完成这些后再进入发布/部署流程；本文不授权或声称已经部署。

| 非线性分布 | 构造人口和平均资金相同但跨不同档的分布，得到符合明确测试表的差异；同档拆分/合并保持一致 |

| 支持集 | 无供应、外部E=0、无订阅、q=0、整组不可用；不由正倍率创造原本不存在的需求 |
| map隔离 | 同市场两国以A→B→A顺序重复刷新与单独刷新一致；先删后加，清理幂等，无上国残值 |
| 资金准备 | 每完整刷新每地点一次；raw-only、小国、求解器关闭、无市场也不读旧轮资金 |
| 外部modifier | 正负外部offset、自身旧scale、重复刷新、关闭重开；无自我累积或双乘 |
| 兼容 | 五目标全1与非中性测试；PP特殊商品、M&T价格/维护、JTG86商品、奴隶与部落 |
| 生命周期 | 新局、旧档缺版本、普通读档、失地灭国、新国家、换市场、开关；无GUI状态写入与重复迁移 |
| 求解记账 | 矩阵确实使用最终effective；资金目标不因曲线改变；不增加迭代，原有回退可达 |
| 定点 | 独立Decimal/定点模拟报告对float oracle偏差，含极小人口、极高资金与多地点累加；不得添加任意分母下限隐藏误差 |
| 原生需求 | 等待引擎需求刷新后对照商品modifier、实际人口需求与内部支出；区别原生抑制因素，不只验缓存 |

定点容差须按实际表达式的运算顺序和舍入累计设定并写入报告，不对所有规模硬套同一个绝对epsilon。float oracle可用严格相对容差；不能据此声称引擎定点等价。性能测试同时报告中性表与非中性表，区分纯工程开销和经济变化导致的求解分支变化。
